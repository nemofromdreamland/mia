# 5.1 — Cliente local do Nova 2 Sonic

## Contexto

O Gate 0 aprovou qualitativamente o Nova 2 Sonic em pt-BR, mas não mediu latência. Esta tarefa adapta o cliente Python oficial para abrir e encerrar corretamente uma sessão bidirecional no terminal, reutilizar as regras curtas do entrevistador v2 e medir o tempo até a primeira fala. Fontes: Implementation Plan (Fase 5), TRD (Arquitetura, Stack e Segurança e LGPD), ADR 0001 e documentação oficial do Nova 2 Sonic.

## Requisitos

- R1. QUANDO o cliente local inicia com configuração válida e um transporte Sonic disponível, O SISTEMA DEVE abrir a sessão bidirecional na ordem exigida pelo protocolo oficial e encerrá-la com `contentEnd`, `promptEnd` e `sessionEnd`, mesmo após erro ou interrupção do usuário.
- R2. QUANDO a sessão de voz começa, O SISTEMA DEVE usar a voz feminina pt-BR configurada.
- R3. QUANDO a configuração de voz é carregada, O SISTEMA DEVE obter o id da voz de `config/voice.yaml`, permitindo sobrescrita por `MIA_VOICE_ID`, sem manter o id como constante de código.
- R4. QUANDO a configuração padrão do projeto é usada, O SISTEMA DEVE selecionar `carolina`, identificada pela AWS como a voz feminina do locale `pt-BR` para o Nova 2 Sonic.
- R5. QUANDO o prompt da sessão é enviado, O SISTEMA DEVE instruir a MIA a falar em português do Brasil, concordar no feminino e respeitar a regra do entrevistador v2 de no máximo 3 frases curtas e 60 palavras por fala.
- R6. QUANDO o microfone produz áudio, O SISTEMA DEVE enviar PCM 16 kHz, 16 bits, mono em blocos no ritmo da captura; QUANDO o Sonic produz áudio, O SISTEMA DEVE reproduzir PCM 24 kHz, 16 bits, mono e exibir apenas as transcrições textuais recebidas.
- R7. QUANDO qualquer evento de saída do Sonic é recebido, O SISTEMA DEVE validá-lo com um schema Pydantic antes de encaminhar áudio ou transcrição; evento desconhecido ou inválido deve encerrar a sessão com erro claro.
- R8. QUANDO o cliente abre a sessão, O SISTEMA DEVE medir monotonicamente o tempo até o primeiro `audioOutput`, mostrá-lo no terminal e incluí-lo no registro da execução.
- R9. QUANDO uma sessão termina ou falha, O SISTEMA DEVE gravar um `RunRecord` sem bytes de áudio bruto, contendo metadados da configuração, transcrições mascaradas e latência; nenhum áudio deve ser persistido.
- R10. QUANDO os testes rodam sem AWS e sem dispositivo de áudio, O SISTEMA DEVE aceitar transporte, relógio, captura e reprodução falsos para verificar configuração, ordem dos eventos, validação, métricas e limpeza de recursos.
- R11. QUANDO o usuário executa o comando local com uma conta AWS habilitada, O SISTEMA DEVE permitir uma conversa pelo terminal, com entrada pelo microfone, saída no fone e encerramento explícito, usando apenas CV, vaga e respostas fictícios.

## Fora de escopo

- Ferramentas e máquina de estados do `interviewer.py`, pontuação e persistência de turnos (5.2).
- Protocolo WebSocket próprio da MIA (5.3), navegador (5.4) e URL SigV4 do AgentCore (5.5).
- Limite de 90 s por resposta, dicas, cotas e kill switch, que entram nas specs seguintes.
- Deploy, comandos AWS, gravação da demo e armazenamento de áudio.

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `config/voice.yaml` | criar | modelo, região, locale, `voice_id` e formatos de áudio; padrão documental `carolina` |
| `src/mia/schemas.py` | alterar | configuração validada e união discriminada dos eventos Sonic consumidos |
| `src/mia/llm.py` | alterar | único adaptador que importa o SDK Bedrock bidirecional, invoca o modelo e fecha o stream |
| `src/mia/voice/__init__.py` | criar | pacote de voz |
| `src/mia/voice/sonic.py` | criar | sessão, eventos, filas, áudio injetável, prompt, transcrição e métrica de primeira fala |
| `src/mia/voice/console.py` | criar | entrada do terminal e composição dos adaptadores reais de microfone/fone |
| `pyproject.toml`, `uv.lock` | alterar | SDK experimental usado pelo exemplo oficial e biblioteca de áudio, com versões travadas |
| `tests/test_sonic.py` | criar | testes offline do protocolo, configuração, schemas, métrica e falhas |
| `tests/test_voice_console.py` | criar | composição do terminal sem dispositivo real |

**Interfaces**

```python
class VoiceConfig(BaseModel): ...
class SonicEvent(BaseModel): ...

class SonicTransport(Protocol):
    async def send(self, event: dict[str, object]) -> None: ...
    async def receive(self) -> AsyncIterator[dict[str, object]]: ...
    async def close(self) -> None: ...

class AudioInput(Protocol):
    async def chunks(self) -> AsyncIterator[bytes]: ...
    async def close(self) -> None: ...

class AudioOutput(Protocol):
    async def play(self, chunk: bytes) -> None: ...
    async def close(self) -> None: ...

def load_voice_config(path: Path = Path("config/voice.yaml")) -> VoiceConfig: ...
async def open_sonic_transport(config: VoiceConfig) -> SonicTransport: ...
async def run_sonic_session(
    config: VoiceConfig,
    transport: SonicTransport,
    audio_in: AudioInput,
    audio_out: AudioOutput,
    clock: Callable[[], float],
) -> RunRecord: ...
def main() -> int: ...
```

**Decisões**

- A documentação oficial vigente lista `carolina` como voz feminina `pt-BR`; o valor fica no YAML e pode ser sobrescrito por env, nunca em constante Python.
- `llm.py` contém o import e a chamada ao SDK específico da AWS. `voice/sonic.py` conhece somente o protocolo injetado, preservando o ponto único de chamadas a modelos.
- O cliente parte do exemplo oficial Python completo do Nova 2 Sonic, mas separa transporte e áudio para que todos os critérios de protocolo rodem offline.
- O prompt reutiliza as regras já aprovadas do `interviewer` v2 e acrescenta apenas idioma e concordância feminina; não cria uma chamada de modelo de texto adicional.
- Um stream completo gera um `RunRecord`; bytes de áudio e credenciais nunca entram em log. As transcrições passam por `pii.py` antes de persistir no registro.
- O teste manual usa fone para reduzir eco e dados inteiramente fictícios. A credencial vem da cadeia padrão da AWS, nunca de arquivo do projeto.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| configuração padrão | `voice.yaml` sem env | `voice_id == "carolina"`, locale `pt-BR` |
| sobrescrita | `MIA_VOICE_ID=voz-teste` | evento `promptStart.audioOutputConfiguration.voiceId == "voz-teste"` |
| configuração inválida | id vazio ou taxa incompatível | erro de configuração antes de abrir transporte |
| início | transporte falso | eventos na ordem `sessionStart`, `promptStart`, prompt do sistema, início do áudio |
| voz e prompt | config falsa + prompt | evento leva o id configurado; texto exige pt-BR, feminino e até 3 frases/60 palavras |
| áudio | bloco PCM falso de entrada e `audioOutput` falso | entrada codificada é enviada; saída é entregue uma vez ao player |
| transcrição | eventos parciais e finais válidos | texto é exibido; nenhum byte de áudio é gravado |
| evento inválido | payload sem campos obrigatórios | erro claro, streams e áudio fechados |
| primeira fala | relógio falso 10,0 → 11,25 | terminal e `RunRecord.latency_ms` registram 1250 ms |
| encerramento normal | sinal de saída do usuário | `contentEnd` → `promptEnd` → `sessionEnd`; recursos fechados uma vez |
| falha no stream | exceção após abrir áudio | tentativa de fechamento ordenado; `RunRecord.error` preenchido |
| sem AWS/dispositivo | todos os adaptadores falsos | suíte passa sem rede, credenciais, microfone ou fone |
| conversa real | conta AWS nova + fone | MIA fala com voz feminina pt-BR; usuário ouve, responde e encerra |

## Critérios de aceite

**Offline (não requer AWS)**

- [ ] A configuração da sessão Sonic leva exatamente o id de voz configurado ao `promptStart` — verificar com: `uv run pytest tests/test_sonic.py -v`
- [ ] Fakes cobrem ordem de eventos, prompt curto em pt-BR/feminino, áudio, schemas, primeira fala, falhas e fechamento sem rede ou hardware — verificar com: `uv run pytest tests/test_sonic.py tests/test_voice_console.py -v`
- [ ] Nenhum teste ou registro persiste áudio bruto — verificar com: `uv run pytest tests/test_sonic.py -v`
- [ ] `uv run pytest` passa
- [ ] `uv run ruff check .` passa

**Com AWS — depende de uma conta AWS nova**

- [ ] Conversa local pelo terminal funciona — verificar com: `uv run python -m mia.voice.console`
- [ ] O dono ouve a MIA falar com voz feminina em português do Brasil numa conversa real com fone.
- [ ] O tempo até a primeira fala é exibido e registrado como evidência, sem áudio bruto.

## Perguntas em aberto

1. Qual conta/região usar para a voz? → resposta: conta AWS nova em `us-east-1`, mantendo a região do projeto.
2. A exceção inevitável ao mascaramento pré-LLM está aprovada? No speech-to-speech, o áudio chega ao Sonic antes de existir transcrição para `pii.py`. → resposta: sim, restrita ao Sonic; aceitar só dados fictícios, mascarar antes de persistir e documentar consentimento.
3. O `RunRecord` atual representa adequadamente uma sessão de streaming? → resposta: acrescentar campos opcionais retrocompatíveis (`first_audio_ms`, duração e contagem de eventos) e nunca armazenar áudio.
4. O comando público deve ser módulo ou subcomando? → resposta: usar `uv run python -m mia.voice.console` nesta tarefa e deixar um CLI público para mudança explícita futura.
