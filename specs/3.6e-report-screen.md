# 3.6e — Tela Relatório

## Contexto

Bloco 4 da seção 14 do Design: `/sessao/:id/relatorio` mostra a nota geral, as competências, o que melhorar, a avaliação resposta por resposta e a transcrição; "Treinar este caso de novo" cria outra sessão do mesmo caso. Fontes: `docs/design/05-telas.md` (6.6), `04-componentes.md` (5.9, 5.14, 5.16–5.18, 5.20, 5.33), `06` (9.1), `07` (10.1, 13), `BACKEND_SCHEMA` (`ReportView`, `Report`, `Turn`, `AnswerScore`).

## Requisitos

- R1. QUANDO a tela abre, O SISTEMA DEVE chamar `GET /sessions/:id`; status fora de `scoring`/`completed` redireciona por `routeForStatus`; `not_found` mostra a tela inteira da 3.6c.
- R2. QUANDO o status é `scoring`, O SISTEMA DEVE mostrar MiaMark 48 `thinking` + "A MIA está avaliando suas respostas. Isso costuma levar menos de um minuto." e fazer polling a cada 2 s; ao virar `completed`, carregar o relatório na mesma tela.
- R3. QUANDO o status é `completed`, O SISTEMA DEVE chamar `GET /sessions/:id/report` e `GET /sessions`, com skeleton (cabeçalho, bloco da nota, 3 linhas de competência) enquanto carrega.
- R4. O cabeçalho DEVE mostrar "FEEDBACK DA MIA" (`label mia`), `h1` com `job_title` e "{Entrevista técnica} · {15 de novembro de 2026} · {18 min} · {7 perguntas}" (data de `ended_at` em `dateStyle: long`; duração `ended_at − started_at` arredondada; perguntas = `question_id` distintos).
- R5. A nota geral (`data-testid="overall-score"`) DEVE mostrar "NOTA GERAL", o número em `text-display` + "de 5", RubricScore `md` com rótulo e, se houver tentativa anterior (sessão `completed` mais recente do visitante com o mesmo `case_id` e `created_at` anterior), "Tentativa anterior neste caso: 3,2" sem seta e sem cor.
- R6. QUANDO `is_above_case_avg` é verdadeiro, O SISTEMA DEVE mostrar a AboveAverageNote: InlineNotice `neutral` com `ClipboardList`, "Sua nota ficou acima da média deste caso." e o link "Ver como o recrutador te vê" (`data-testid="above-average-link"`) para `/recrutador/:id`.
- R7. "Por competência" DEVE listar CompetencyRow (nome `text-h3`, RubricScore `sm` decimal, "antes X" só se o nome for idêntico em `competency_scores` da tentativa anterior, `summary` em `foreground-soft`, divisórias).
- R8. "O que funcionou" DEVE listar `strengths` com `Check` `mia`.
- R9. "O que melhorar" DEVE mostrar um card por `improvement`: "PERGUNTA N" (posição do `question_id`), o texto da pergunta (primeiro turno do `question_id`, serifa 18 px), "O que faltou:" + `issue` e MiaSuggestion "UMA RESPOSTA MAIS FORTE" com `stronger_answer`; vazio → "Nenhum ponto crítico nesta entrevista.".
- R10. "Resposta por resposta" DEVE ser um acordeão fechado por grupo de `question_id`: cabeçalho "Pergunta N" + RubricScore `sm` do primeiro turno; conteúdo com cada turno (aprofundamento com a etiqueta "APROFUNDAMENTO" e nota própria), resposta com `<mark>` nas `evidence_quotes` verificadas, CriteriaList ("CRITÉRIOS ATENDIDOS") e "POR QUE ESSA NOTA" + `justification`. Sem nota → "Esta resposta não foi avaliada."; sem trecho verificado → "Sem trecho destacado para esta resposta."; sem critérios → "Nenhum critério atendido nesta resposta.".
- R11. A transcrição completa DEVE ficar num `<details>` fechado "Mostrar transcrição completa ({n} falas)", com o mesmo visual da Entrevista.
- R12. "Treinar este caso de novo" (default) DEVE chamar `POST /sessions` com o mesmo `case_id` e `mode` e ir para o Preparo; `quota_exceeded`/`demo_paused` mostram o InlineNotice `warning` da 10.1 e desabilitam o botão; outros erros viram toast. "Voltar ao início" (outline) → `/`.
- R13. QUANDO o carregamento falha, O SISTEMA DEVE mostrar InlineNotice `danger` "Não foi possível carregar o feedback." + "Tentar de novo".

**Interfaces**

```ts
// lib/types.ts
export type AnswerScore = { score: number; criteria_met: string[]; evidence_quotes: string[];
  justification: string; quotes_verified?: boolean | null };
export type Turn = PublicTurn & { session_id: string; is_follow_up: boolean; score: AnswerScore | null };
export type CompetencyScore = { competency: string; score: number; summary: string };
export type Improvement = { question_id: string; issue: string; stronger_answer: string };
export type Report = { overall_score: number; competencies: CompetencyScore[]; strengths: string[];
  improvements: Improvement[] };
export type ReportView = { report: Report; turns: Turn[]; is_above_case_avg: boolean | null };

// lib/report.ts
export function previousAttempt(sessions: Session[], current: Session): Session | null;
export type QuestionGroup = { questionId: string; n: number; turns: Turn[] };
export function groupByQuestion(turns: Turn[]): QuestionGroup[];
export function verifiedQuotes(answer: string, score: AnswerScore | null): string[];
export type Segment = { text: string; mark: boolean };
export function highlight(answer: string, quotes: string[]): Segment[];
export function durationMinutes(startedAt?: string | null, endedAt?: string | null): number | null;
export function speechCount(turns: { answer_text: string | null }[]): number;

// components
export function CompetencyRow(p: { item: CompetencyScore; before?: number }): JSX.Element;
export function CriteriaList(p: { items: string[] }): JSX.Element;
export function MiaSuggestion(p: { text: string }): JSX.Element;
export function AboveAverageNote(p: { sessionId: string }): JSX.Element;
export function HighlightedAnswer(p: { answer: string; quotes: string[] }): JSX.Element;
export function FullTranscript(p: { turns: (PublicTurn & { is_follow_up?: boolean })[]; persona: Persona }): JSX.Element;
```

**Decisões**

- `highlight` marca cada trecho na primeira ocorrência, sem sobreposição (trechos que colidem com um já marcado são ignorados), na ordem do texto.
- Duração e data usam `ended_at`/`started_at` do `GET /sessions/:id` (já carregado para checar o status); data cai para `created_at` se `ended_at` faltar.
- O polling do `scoring` usa `usePolling` com o mesmo `GET`; erro não-rede mostra o InlineNotice de erro (R13).
- "Pergunta N" nas falas da transcrição completa vem de `questionNumbers` (3.6d).
- Acordeão: `Accordion type="multiple"` do shadcn, fechado por padrão.
- Celular (12): `text-display` com 40 px, rubrica abaixo do nome na competência, botões empilhados.

## Notas de implementação
- Passo 1: `Turn` estende `PublicTurn` (mesmos campos + `session_id`, `is_follow_up`, `score`); `decision` não foi tipado porque o front não usa. `highlight` ordena os trechos pelo início e ignora os que colidem com um já marcado (o primeiro da lista vence). `previousAttempt` compara `created_at` como string ISO (mesmo formato do backend).
- Passo 2: Componentes em `components/report/`. `RubricScore.showNumber` (padrão `true`) para não repetir o número ao lado do `text-display` e na CompetencyRow (que mostra sempre uma casa decimal, "4,0", seguindo a 5.20). AboveAverageNote é um `role="note"` com o visual do InlineNotice `neutral` e um `<Link>` (o InlineNotice só aceita botão, e aqui a ação é navegação). FullTranscript (usado também na 3.6f) reaproveita `TranscriptTurn` e `QuestionDivider` da Entrevista; o `<summary>` tem `ChevronRight` que gira ao abrir (transição some com "reduzir movimento" pela regra global).
