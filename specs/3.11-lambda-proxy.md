# 3.11 — Lambda proxy

Aprovação: modo autônomo pedido pelo dono.

## Contexto

O navegador nunca fala com o AgentCore: ele chama o API Gateway HTTP API, que invoca uma Lambda proxy. A proxy valida o `X-Visitor-Id`, traduz a rota REST para a `action` do contrato `/invocations` e chama `InvokeAgentRuntime` com as credenciais IAM da própria Lambda (SigV4 feito pelo boto3). Fontes: TRD ("Arquitetura", "Infraestrutura": linha Proxy; estrutura `proxy/`), Backend Schema ("API": tabela de operações, exemplo de chamada ao AgentCore, "Identificação"; "Erros e validação"). O despachante do lado do container já existe (`src/mia/api/invocations.py`, 3.2). Terraform da Lambda/API Gateway fica para a 4.2.

## Requisitos

- R1. QUANDO chega um evento do API Gateway HTTP API (payload 2.0) com método + caminho de uma das 11 rotas da tabela do Backend Schema, O SISTEMA DEVE montar o corpo `{action, visitor_id, session_id, payload}` do exemplo do Backend Schema e chamar `invoke_agent_runtime` uma vez, com `agentRuntimeArn` de `AGENT_RUNTIME_ARN`, `qualifier` de `AGENT_RUNTIME_QUALIFIER` (padrão `DEFAULT`), `contentType`/`accept` `application/json`.
- R2. QUANDO o header `x-visitor-id` falta ou não é UUID v4 canônico (minúsculo), O SISTEMA DEVE responder 422 `{"error": {"code": "invalid_input", "message": "X-Visitor-Id ausente ou inválido.", "retryable": false}}` sem chamar o AgentCore — em todas as rotas (Backend Schema: "toda requisição leva `X-Visitor-Id`").
- R3. QUANDO a rota é do visitante, O SISTEMA DEVE preencher `visitor_id` com o header validado; QUANDO é do recrutador ou `list_cases`, DEVE omitir `visitor_id`. Um `visitor_id` no corpo JSON do navegador NUNCA DEVE chegar ao AgentCore.
- R4. QUANDO a rota tem `{id}`/`{session_id}`, O SISTEMA DEVE enviá-lo em `session_id`; QUANDO é `POST /sessions` ou `POST /sessions/{id}/turns`, DEVE enviar o corpo JSON (sem `visitor_id`) em `payload`; QUANDO é `GET /recruiter/candidates?case_id=`, DEVE enviar `{"case_id": ...}` em `payload` (ou `{}` sem o parâmetro).
- R5. QUANDO método/caminho não estão na tabela, O SISTEMA DEVE responder 404 `not_found` sem chamar o AgentCore; QUANDO o corpo não é JSON objeto válido, 422 `invalid_input`.
- R6. QUANDO o AgentCore responde, O SISTEMA DEVE devolver ao API Gateway `{statusCode, headers: {"content-type": "application/json"}, body}` com o corpo do runtime sem alteração; o `statusCode` vem do código de erro do corpo (tabela "Erros e validação": `not_found` 404, `invalid_input` 422, `invalid_state` 409, `session_limit` 409, `quota_exceeded` 429, `demo_paused` 503, `llm_invalid_output` 502, `provider_unavailable` 503, `internal` 500) ou, sem erro, 201 para `create_session`, 204 (corpo vazio) para `delete_session` e 200 para o resto.
- R7. QUANDO a chamada ao AgentCore levanta erro do boto3/botocore, O SISTEMA DEVE responder 500 `internal` com `retryable: true` e mensagem genérica, sem vazar ARN, credencial ou texto do erro.
- R8. QUANDO o AgentCore é chamado, O SISTEMA DEVE usar `runtimeSessionId` estável: `mia-visitor-<visitor_id>` nas rotas do visitante e `mia-public-<prefixo fixo>` nas públicas, sempre com 33+ caracteres (limite do AgentCore).

## Fora de escopo

- Terraform da Lambda, do API Gateway, CORS e throttling (4.2); permissões IAM (4.1/4.5).
- Rota `POST /sessions/{id}/voice-url` (5.5).
- Chamada real ao AgentCore: o teste usa cliente falso (mock), como o "Pronto quando" pede.
- Empacotamento da Lambda (zip/camada com boto3 recente) — 4.2.

**Arquivos**

**Interfaces**

```python
# proxy/handler.py — só stdlib + boto3 (não importa `mia`: é outra Lambda)
Route = tuple[str, str, bool]          # (action, path kind, needs visitor)
ROUTES: list[tuple[str, re.Pattern[str], str]]   # (method, path regex, action)
STATUS_BY_CODE: dict[str, int]
def parse_visitor_id(value: str | None) -> str | None: ...
def match_route(method: str, path: str) -> tuple[str, str | None] | None: ...   # (action, session_id)
def build_invocation(event: dict[str, Any]) -> dict[str, Any]: ...              # levanta ProxyError
def runtime_session_id(visitor_id: str | None) -> str: ...
def to_http(action: str, body: bytes) -> dict[str, Any]: ...
def handle(event: dict[str, Any], client: Any, arn: str, qualifier: str) -> dict[str, Any]: ...
def lambda_handler(event: dict[str, Any], context: Any) -> dict[str, Any]: ...  # lê env, cria cliente uma vez
class ProxyError(Exception): code: str; message: str
```

**Decisões**

- A proxy não importa `mia`: pacote da Lambda pequeno e independente; a regra do UUID v4 é duplicada (5 linhas) e testada com os mesmos casos do `api/visitor.py`.
- Status HTTP derivado do corpo (código de erro) e da action, não do `statusCode` do AgentCore: o contrato do `/invocations` garante o formato do erro, e assim a proxy não depende de o runtime repassar o status.
- `invalid_input` = 422 (tabela de erros do Backend Schema). A 4.2 cita "sem header → 400"; vale o Backend Schema (prioridade maior) e a 4.2 deve usar 422.
- `runtimeSessionId` por visitante: reaproveita a micro-VM do mesmo visitante entre chamadas (menos cold start); o estado de verdade está no DynamoDB.
- Cliente boto3 criado uma vez por contêiner Lambda (variável de módulo preguiçosa) e injetável em `handle` para teste.

## Notas de implementação

- Passo 1: rotas como lista de regex (`session_id` = `[A-Za-z0-9]+`, o ULID); a ordem não importa porque os padrões são ancorados. O header é validado antes da rota (header inválido em rota desconhecida → `invalid_input`). `visitor_id` do corpo é descartado em `_json_body`. Headers normalizados para minúsculas (o HTTP API já manda assim, mas o teste local pode não mandar). `pythonpath = ["."]` no pytest para importar `proxy.handler`. 35 testes.
- Passo 2: `handle` recebe o cliente (teste injeta um falso com `invoke_agent_runtime` que grava os kwargs); `lambda_handler` lê `AGENT_RUNTIME_ARN`/`AGENT_RUNTIME_QUALIFIER` e usa `_client()` com `functools.cache` (um cliente por contêiner Lambda). Erros do boto3/botocore viram `internal` retryable com a mensagem genérica do backend ("Erro interno. Tente de novo."), sem ARN nem código da AWS. Código de erro desconhecido no corpo do runtime → 500, corpo repassado como veio. Corpo vazio/não JSON sem erro → status pela action. Evento de exemplo em `tests/fixtures/apigw_send_answer.json` (formato 2.0, conta fictícia `000000000000`). 51 testes.
