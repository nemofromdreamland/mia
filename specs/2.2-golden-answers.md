# 2.2 — Gerar as 70 respostas do golden set

## Contexto

O conjunto A avalia o juiz: 10 perguntas × 7 respostas (5 níveis, 1 "enrolada", 1 paráfrase) = 70 itens, que o dono vai notar na 2.3. As respostas são geradas pelo prompt `synthetic_candidate` com Groq (`gpt-oss-120b`), família diferente do juiz (Claude), para o juiz não avaliar a própria família. Fontes: `docs/IMPLEMENTATION_PLAN.md` (Fase 2), `docs/TRD.md` (tabela de prompts e conjunto A), `docs/BACKEND_SCHEMA.md` (`GoldenItem`), `docs/PRD.md` (métricas viés de verbosidade e consistência).

## Requisitos

- R1. QUANDO o script roda sobre `evals/datasets/questions.yaml`, O SISTEMA DEVE gerar exatamente 7 itens por pergunta (variants `level_5`…`level_1`, `rambling`, `paraphrase`), 70 no total, e gravá-los em `evals/datasets/judge_golden.jsonl`, um JSON por linha.
- R2. QUANDO um item é gravado, O SISTEMA DEVE validá-lo pelo schema de rascunho (ver P1) e usar `item_id = <question_id>-<variant>` (ex.: `gq-tech-01-level_3`), único no arquivo.
- R3. QUANDO o item é `paraphrase`, O SISTEMA DEVE preencher `paraphrase_of` com o `item_id` da resposta parafraseada (ver P2); nos demais, `paraphrase_of = null`.
- R4. QUANDO o modelo é chamado, O SISTEMA DEVE usar `run_prompt` com o prompt `synthetic_candidate` (modelo vindo de `config/models.yaml`, hoje `groq:openai/gpt-oss-120b`), passar o CV do caso mascarado por `pii.mask_cv` e gravar o `RunRecord` com `experiment="golden-2.2"`.
- R5. QUANDO o item é gravado, O SISTEMA DEVE preencher `generated_by` com `"<modelo>|synthetic_candidate@v<N>"` (ex.: `groq:openai/gpt-oss-120b|synthetic_candidate@v1`).
- R6. QUANDO a resposta do modelo vem vazia (só espaços), O SISTEMA DEVE falhar com erro claro citando o `item_id`, sem gravar arquivo parcial.
- R7. QUANDO o arquivo de saída já existe, O SISTEMA DEVE recusar sobrescrever sem a flag `--force` (as notas humanas da 2.3 não podem ser perdidas por engano).
- R8. QUANDO os testes rodam, O SISTEMA NÃO DEVE chamar modelo real (chat model falso injetado).
- R9. QUANDO o arquivo commitado é lido, O SISTEMA DEVE ter 70 itens válidos, 7 variants por pergunta e nenhum dado pessoal (`mask_text(answer_text) == answer_text`).

## Fora de escopo

- Notas humanas e split dev/teste (tarefa 2.3).
- Rodar o juiz sobre os itens, Promptfoo, métricas (2.5+).
- Conjuntos B, C e D (2.4).
- Revisar a qualidade de cada resposta além do básico: o dono lê na 2.3 e pode pedir regeneração de itens.

**Interfaces**

```python
# scripts/build_golden.py
QUESTIONS_PATH: Final[Path]
OUTPUT_PATH: Final[Path]
QUESTION_CASE: Final[dict[str, str]]          # question_id -> case_id (P3)
VARIANTS: Final[tuple[Variant, ...]]          # ordem de geração
TARGETS: Final[dict[Variant, tuple[str, str]]]  # variant -> (target_score, style)

def load_questions(path: Path = QUESTIONS_PATH) -> list[Question]: ...
def generate_answer(question: Question, variant: Variant, cv_masked: str, *,
                    chat_model: BaseChatModel | None = None,
                    base_answer: str | None = None) -> str: ...
def build_items(questions: list[Question], *, chat_model: BaseChatModel | None = None,
                cases_dir: Path = CASES_DIR) -> list[GoldenItem]: ...
def write_jsonl(items: list[GoldenItem], path: Path, *, force: bool) -> None: ...
def main(argv: Sequence[str] | None = None, *, chat_model: BaseChatModel | None = None) -> int: ...
```

`Variant` = o `Literal` dos variants, exposto em `schemas.py` como alias de tipo.

**Decisões**

- Script em `scripts/` (como `build_cases.py`), não comando da CLI: roda uma vez, não faz parte do produto.
- Gera tudo em memória e só grava no fim: falha no meio não deixa arquivo pela metade (R6).
- CV do caso dá contexto realista ao candidato; vem de `load_case_texts` e passa por `mask_cv` antes do LLM.
- `TARGETS` mapeia variant → variáveis do prompt: `level_N` → `target_score="N"`; `rambling` → `"enrolada"`; `paraphrase` conforme P2. `style` curto e fixo por variant (ex.: "direto", "prolixo").
- Nenhuma dependência nova.

## Perguntas em aberto

- P1. O `GoldenItem` exige `human_score` (1–5) e `split`, mas a 2.2 entrega "sem nota". Proposta: tornar os dois opcionais (`int | None = None`, `Literal[...] | None = None`) e a 2.3/2.5 checam que estão preenchidos. Alternativa: o script grava um formato de rascunho separado. Isso muda o `BACKEND_SCHEMA.md` também. → resposta: opcionais (`None` por padrão); `BACKEND_SCHEMA.md` atualizado.
- P2. O que é a "paráfrase"? O prompt v1 diz "repete a pergunta com outras palavras" (seria uma resposta vazia, nota ~1), mas o schema tem `paraphrase_of` e o PRD usa paráfrases para medir **consistência** do juiz, o que sugere: mesma resposta de um item (ex.: `level_3` ou `level_4`) reescrita com outras palavras, e o juiz deveria dar a mesma nota. Proposta: a segunda leitura, parafraseando o `level_3`; exige `prompts/synthetic_candidate/v2.yaml` com variável `{base_answer}` e changelog. → resposta: paráfrase do `level_3`, via `synthetic_candidate/v2.yaml` com `{base_answer}`.
- P3. `questions.yaml` não diz de qual caso é cada pergunta (só comentários). Proposta: dict `QUESTION_CASE` no script (2 perguntas por caso, conforme a 2.1). Alternativa: gerar sem CV (`cv` vazio). → resposta: dict `QUESTION_CASE` no script.
- P4. Groq tem chave no `.env` e cota suficiente para 70 chamadas (~600 tokens cada)? → resposta: assumido que sim; confirmado no passo 3.

Evidências: `specs/2.2-evidence.md` (preenchido no verify)

## Notas de implementação

- Passo 1: `Variant` virou alias público em `schemas.py`; `human_score` e `split` passam a ser opcionais (`None` até a 2.3), também no `BACKEND_SCHEMA.md`. Testes antigos de faixa 1–5 e split inválido continuam valendo. 596 testes passam, cobertura 98,81%.
- Passo 2: `prompts/synthetic_candidate/v2.yaml` tem `{base_answer}` dentro de `<resposta_base>` (vazio nos outros variants) e changelog. O script fixa `PROMPT_VERSION = 2`. `generate_answer`, `build_items` e `_question_items` aceitam `runs_dir` (não estava na assinatura da spec) para os testes não escreverem em `runs/`. `main` checa o arquivo de saída antes de chamar o modelo, para não gastar cota à toa. 608 testes passam, cobertura 98,81%.
