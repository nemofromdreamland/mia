# 6.4 — Documentação pública do portfólio

## Contexto

A conta AWS fecha em 17/11 e a demo sai do ar; o repositório (público) passa a ser o portfólio (Fase 6 do `docs/IMPLEMENTATION_PLAN.md`, tarefas 6.4 e 6.5). Esta spec junta as duas: README + `docs/` em inglês, com números verificáveis, precedidos de uma auditoria de sigilo e dados pessoais. Decisões do grill de 17/11 registradas em "Decisões".

## Requisitos

- R1. QUANDO qualquer documento público for publicado (commit), O SISTEMA DEVE ter passado antes pela auditoria de sigilo, com zero achados não justificados em HEAD e no histórico.
- R2. QUANDO a auditoria rodar, ELA DEVE procurar em todos os commits (`git rev-list --all`) e no working tree: chaves (AKIA/ASIA, `gsk_`, `sk-`, `pk-lf-`, `AIza`), ARNs/IDs de conta AWS de 12 dígitos, URLs de API Gateway/CloudFront/ECR, nomes de bucket, `*.tfstate`/`*.tfvars`/`.env*` rastreados, e-mails, telefones, CPFs, nomes de usuário (Windows/GitHub) e caminhos `C:\Users\...`; a saída mostra só arquivo, linha, tipo e valor mascarado (6 primeiros + `***` + 2 últimos).
- R3. QUANDO um achado for aceito, O SISTEMA DEVE registrá-lo numa allowlist versionada com justificativa (ex.: domínio `example.com`, ID falso `123456789012`), e a auditoria não deve mais contá-lo.
- R4. QUANDO o ID da conta AWS, URLs de API Gateway/CloudFront e nomes de bucket reais aparecerem em HEAD, O SISTEMA DEVE trocá-los por placeholders (`<account-id>`, `<api-id>`, `<distribution>`); no histórico ficam aceitos com a justificativa "conta encerrada em 17/11".
- R5. QUANDO os runs de produção (`runs/2026-11-17_aws-*.jsonl`) forem revisados, O SISTEMA DEVE classificar os `input` de texto livre como "dono/fictício" ou "terceiro"; havendo terceiro, o arquivo sai do HEAD, `runs/*aws*` entra no `.gitignore` e a reescrita do histórico é proposta ao dono (só com confirmação explícita).
- R6. QUANDO a regra de idioma for aplicada, `AGENTS.md` e a skill afetada, nos dois agentes (`.claude/skills/` e `.agents/skills/`), DEVEM dizer: README e `docs/` públicos novos (architecture, security, evaluation, prompt-guide, running-locally, costs, adr novos) em inglês; PRD, TRD, APP_FLOW, CASES, design e specs continuam em português.
- R7. QUANDO um documento citar um número (métrica, custo, latência, contagem), ELE DEVE vir de um arquivo em `results/`, `runs/` ou `config/` e ser reproduzível por um comando listado em `docs/evaluation.md` ou `docs/costs.md`; número sem fonte não é citado.
- R8. QUANDO a latência de voz for citada, ELA DEVE ser mediana e p90 de `latency_ms` dos registros `voice_interviewer` em `runs/`, calculadas pelo script de números; o valor "1,2 s" não é citado se não sair do cálculo.
- R9. QUANDO o custo de voz for citado, O SISTEMA DEVE mostrar só tokens/turnos medidos e a frase "price not confirmed" enquanto `config/models.yaml` marcar o preço do Nova 2 Sonic como a confirmar.
- R10. QUANDO o README for aberto no GitHub, ELE DEVE mostrar no topo `docs/assets/mia.svg` (MiaMark, estado idle, 96 px, estático), legível nos temas claro e escuro, e ser lido em ~2 minutos: objetivo, GIF da demo, arquitetura em 1 diagrama, método, resultados com números, limitações, modelo de ameaças resumido, links para `docs/`.
- R11. QUANDO a demo for mostrada, O SISTEMA DEVE usar mídia derivada de `media/demo-desktop.webm` (modo texto, tarefa 4.9): um GIF ≤ 5 MB em `docs/assets/demo.gif` e um MP4 enviado como anexo do GitHub (link no README); a voz aparece por descrição e trecho de transcrição, sem vídeo. Toda mídia passa pela auditoria visual (sem dado pessoal, URL real ou ID de conta na tela).
- R12. QUANDO um ADR for escrito, ELE DEVE tratar de uma decisão só, em inglês, no formato Context / Decision / Consequences, com links para a spec de origem.

**Decisões** (grill de 17/11)

- Público em camadas: recrutador lê o README em 2 min; o revisor técnico segue para `docs/`.
- Inglês só no README e nos `docs/` novos; o processo (specs, PRD) fica em português.
- Conta/URLs: mascarar em HEAD, aceitar no histórico (conta encerrada). Sem reescrita de histórico nesta etapa.
- Runs de produção: revisão manual por amostragem dentro do passo 1; a decisão depende do que aparecer.
- Mídia: a gravação de voz foi abortada; GIF + MP4 saem do vídeo de texto da 4.9. `ffmpeg` é ferramenta local do dono (`winget install Gyan.FFmpeg`), fora do `pyproject.toml`.
- Mascote: só no README; as cores do MiaMark são fixas, então um SVG sem `currentColor` serve nos dois temas (confirmar com prints).
- Autoria dos ADRs e do guia de prompts: o agente escreve, o dono aprova (desvio aprovado do "com suas palavras" da 6.5).
- Tamanho: README com ~150 linhas; cada doc com 1–3 telas; diagramas em Mermaid (o GitHub renderiza).
- Nenhuma dependência nova: os scripts usam a stdlib + `pydantic`/`pyyaml` já existentes.

## Notas de implementação

- Passo 1: a varredura do histórico lê `git log --all -p` (toda linha já adicionada) em vez de `git grep` em 335 commits: uma passada, com número de linha. Nomes pessoais nunca ficam no repo: entram por `MIA_AUDIT_IDENTITIES` na hora de rodar. Conta, API Gateway, CloudFront e buckets mascarados em `specs/4.*` (HEAD). Runs de produção: 65 respostas distintas, várias em primeira pessoa e transcrições de voz que podem ser de terceiros → saíram do HEAD (`git rm --cached`), `runs/*aws*` no `.gitignore`; seguem no histórico até o dono decidir reescrever (não feito: exige confirmação explícita).
- Passo 2: R8 usa `params.first_audio_ms` (desvio registrado acima). Mediana medida: 1,31 s (p90 1,49 s, n=11); o "1,2 s" não é citado. Os runs de produção ficam fora do git, então `doc_numbers.py --write-production` grava só agregados (contagens, custo, tokens, latência; nenhum texto) em `results/production_summary.md`, que é a fonte versionada. Tirei "JSON válido na 1ª tentativa" do resumo: o campo é falso para prompts em prosa e o número enganaria. O custo por entrevista é "todas as chamadas do dia ÷ relatórios" (inclui sessões abandonadas, então é um teto).
