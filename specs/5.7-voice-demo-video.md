# 5.7 — Vídeo de demo da voz

## Contexto

A voz (specs 5 e 5.6) foi para produção em 17/11 e a conta AWS fecha à meia-noite do mesmo dia. Esta tarefa grava, de forma 100% automatizada, o vídeo de demo da entrevista por voz, reaproveitando a base da 4.9 (Playwright, legenda narrada pela mascote). Nada de código de produção muda.

## Requisitos

- R1. QUANDO o script roda, O SISTEMA DEVE usar um contexto de navegador novo (visitante novo) contra a URL de produção.
- R2. QUANDO o roteiro pede uma resposta falada, O SISTEMA DEVE entregar ao app, como microfone, um áudio pt-BR gerado por TTS a partir de um texto fictício do personagem do caso.
- R3. QUANDO o app toca qualquer áudio (voz da MIA, "Ouvir"), O SISTEMA DEVE capturá-lo e o vídeo final DEVE conter esse som sincronizado.
- R4. QUANDO o vídeo é gravado, O SISTEMA DEVE seguir o roteiro: seletor Texto | Voz → Preparo (abrir uma seção) → 1ª pergunta falada → Gravar/Parar/Ouvir/Apagar/Gravar/Enviar → balão de áudio → retorno curto → Sugestão de resposta (forte e fraca) e resposta lendo a forte → tentativa de injection → "Vamos manter o foco na entrevista." → Encerrar → relatório (nota, evidências, marca de sugestões) → recrutador.
- R5. QUANDO textos de legenda e respostas são definidos, O SISTEMA DEVE passá-los por `findSensitive` (nenhum padrão encontrado), e os frames conferidos não DEVEM mostrar nome real, e-mail, caminho local, ID de conta nem URL de API.
- R6. QUANDO a gravação termina, a duração DEVE ficar entre 3 e 5 min, com no máximo 4 gravações completas no total.

## Fora de escopo

- Mudanças em `src/`, `frontend/src/`, `infra/`, `prompts/`, `docs/`; deploy, terraform, push.
- Vídeo mobile (só se sobrar tempo).
- Criar qualquer recurso na AWS (Polly só `synthesize-speech`).

## Design

**Arquivos** (scripts e vídeos em `media/`, ignorado pelo git; versionados só a spec e a evidência)

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `media/scripts/voice_script.mjs` | criar | `VOICE_CAPTIONS`, `VOICE_ANSWERS` (id → texto), `INJECTION` |
| `media/scripts/voice_script.test.mjs` | criar | `node --test`: tudo passa no `findSensitive` |
| `media/scripts/tts_answers.mjs` | criar | Polly → `media/voice/<id>.pcm` (16 kHz mono) |
| `media/scripts/record_voice_demo.mjs` | criar | grava com microfone falso e captura de áudio |
| `media/demo-voice-desktop.webm` | criar | vídeo final (vídeo + áudio) |

**Interfaces**

```js
// init script (página)
window.__mia.setAnswer(base64Pcm16k)   // próximo getUserMedia toca este áudio
window.__mia.startCapture() / stopCapture(): Promise<base64Webm>
```

**Decisões**

- Microfone: Amazon Polly (voz neural `Camila`, `pcm` 16 kHz, perfil `mia`) gera um arquivo por resposta, uma vez, antes da gravação. Um `addInitScript` substitui `navigator.mediaDevices.getUserMedia` por um `MediaStream` de um `AudioContext` que toca a resposta da vez, seguida de silêncio. Mais controlável que `--use-file-for-fake-audio-capture` (um arquivo único em loop para a sessão toda).
- Áudio e vídeo no navegador, sem ffmpeg (decisão do dono, 17/11): o dono não quer instalar nada. O Chromium roda com janela (headed), com `--auto-accept-this-tab-capture` / `--use-fake-ui-for-media-stream` e `--autoplay-policy=no-user-gesture-required`. O init script captura a própria aba com `getDisplayMedia({preferCurrentTab})` e envolve `AudioNode.prototype.connect`: toda conexão a `ctx.destination` também vai para um `MediaStreamDestination`, misturado num contexto mestre. O vídeo da aba e o áudio misturado entram num único `MediaRecorder` → `.webm` com som, já sincronizado. Reserva, se a captura da aba falhar: `ffmpeg-static` baixado só no scratchpad, para juntar áudio e vídeo do Playwright.
- A resposta que lê a "Resposta forte" é gerada no Polly durante a gravação, a partir do texto mostrado na tela (passa no `findSensitive` antes).
- Navegação ao recrutador por link interno (sem `page.goto`), para não perder a captura antes de baixá-la.
