# 3.3 — Repositório DynamoDB de sessões e turnos

## Contexto

A 3.1 criou o protocolo `SessionRepository` e a implementação em memória; na AWS as sessões e turnos vivem nas tabelas `mia-sessions` e `mia-turns`. Esta tarefa cria a implementação DynamoDB do mesmo protocolo, com toda mudança de estado feita por `UpdateItem` condicionado ao status anterior. Fontes: `BACKEND_SCHEMA.md` → "Ciclo de vida da sessão", "DynamoDB" (tabelas, GSI `by_case`, padrões de acesso); `TRD.md` → tabela de dados; regra de arquitetura "interface + memória + DynamoDB".

## Requisitos

- R1. QUANDO `create_session` recebe uma `Session` nova, O SISTEMA DEVE gravar um item em `mia-sessions` (`PK=visitor_id`, `SK=session_id`) com `PutItem` condicionado a o item não existir; se já existir, DEVE levantar `SessionConflictError`.
- R2. QUANDO `get_session` é chamado com (`visitor_id`, `session_id`) existente, O SISTEMA DEVE devolver uma `Session` igual à gravada (datas, floats e dicts preservados); se o par não existir (inclusive sessão de outro visitante), DEVE levantar `SessionNotFoundError`.
- R3. QUANDO `update_session` é chamado e o status atual é igual a `expected_status`, O SISTEMA DEVE aplicar `changes` + `updated_at=clock()` em um único `UpdateItem` com `ConditionExpression` sobre o `status` e devolver a `Session` atualizada.
- R4. QUANDO o status atual difere de `expected_status`, O SISTEMA DEVE levantar `SessionConflictError` sem alterar o item; QUANDO a sessão não existe, DEVE levantar `SessionNotFoundError`.
- R5. QUANDO `changes` contém campo de chave (`visitor_id`, `session_id`, `created_at`, `updated_at`) ou gera uma `Session` inválida, O SISTEMA DEVE levantar `ValueError` ANTES de chamar o DynamoDB.
- R6. QUANDO `put_turn` é chamado para sessão existente do visitante, O SISTEMA DEVE gravar (ou sobrescrever) o item em `mia-turns` (`PK=session_id`, `SK=turn_no`); para sessão inexistente ou de outro visitante, DEVE levantar `SessionNotFoundError` e não gravar.
- R7. QUANDO `list_turns` é chamado, O SISTEMA DEVE devolver os turnos em ordem crescente de `turn_no` via `Query` (com paginação); sessão inexistente → `SessionNotFoundError`.
- R8. QUANDO `list_sessions(visitor_id)` é chamado, O SISTEMA DEVE devolver só as sessões do visitante, mais novas primeiro (mesma ordem da memória: `created_at`, depois `session_id`, decrescente).
- R9. QUANDO `list_completed(case_id)` é chamado com `case_id`, O SISTEMA DEVE fazer `Query` no GSI `by_case` e devolver só sessões `completed` desse caso; sem `case_id`, DEVE devolver as `completed` de todos os casos (ver pergunta 1).
- R10. QUANDO `delete_session` é chamado para sessão existente, O SISTEMA DEVE apagar o item da sessão e todos os seus turnos (`BatchWriteItem`); sessão inexistente → `SessionNotFoundError`.
- R11. QUANDO a mesma bateria de testes de contrato roda contra `InMemorySessionRepository` e `DynamoSessionRepository`, O SISTEMA DEVE passar igual nas duas.

## Fora de escopo

- `ReportStore` em S3 e `CandidateCounter` em `mia-meta` (contador entra com cotas na 3.4, ver pergunta 2).

**Decisões**

- `boto3.resource("dynamodb").Table(...)` (API de alto nível): converte tipos sozinha e é o que o moto simula melhor. Tabelas injetadas no construtor → testes passam tabelas do moto; `from_env` é o atalho de produção.
- Conversão: `datetime` → string ISO 8601 (o GSI ordena por `ended_at` como string, que funciona porque tudo é UTC); `float` → `Decimal(str(x))` e de volta; campos `None` não são gravados (GSI esparso: só sessões com `ended_at` entram no `by_case`). Volta sempre por `Session.model_validate` / `Turn.model_validate` — nada de dict solto.
- `update_session`: valida as mudanças em Python (mesma regra da memória: monta a `Session` resultante com o item atual), depois `UpdateItem` com `SET` dos campos alterados, `REMOVE` dos que viraram `None`, `ConditionExpression = attribute_exists(session_id) AND #status = :expected` e `ReturnValues=ALL_NEW`. Se a condição falhar, um `GetItem` decide entre `SessionNotFoundError` (não existe) e `SessionConflictError` (status mudou). O condicional é o que protege contra duas requisições simultâneas.
- `ClientError` com `ConditionalCheckFailedException` vira os erros do domínio; qualquer outro `ClientError` sobe como `RepositoryError` (a 3.2 já mapeia o resto para `internal`).
- `list_completed` sem `case_id` faz `Scan` com filtro `status = completed` (pergunta 1).
- `put_turn` e `list_turns` checam a posse com `GetItem` em `mia-sessions` antes (a tabela de turnos não tem `visitor_id`).
- Toda `Query`/`Scan` segue `LastEvaluatedKey` até o fim.
- Dependências novas: `boto3` (SDK oficial da AWS, necessário em produção) e `moto` (simula DynamoDB local, testes sem rede nem custo).

## Plano de testes

Contrato (roda nas duas implementações, fixture `repo` parametrizada; moto via `mock_aws` com credenciais falsas):

| Caso | Entrada | Esperado |
| --- | --- | --- |
| criar e ler | `create_session(s)`; `get_session("local", "01SESSION")` | `== s` |
| criar duplicada | `create_session(s)` duas vezes | `SessionConflictError` |
| outro visitante | `get_session("outro", "01SESSION")` | `SessionNotFoundError` |
| update feliz | `preparing` → `{"status": "ready", "fit_score": 80}` | status `ready`, `fit_score=80`, `updated_at=T1` (clock fixo) |
| update status errado | `expected_status="ready"` com sessão `preparing` | `SessionConflictError`; `get_session` ainda `preparing` |
| update inexistente | sessão não criada | `SessionNotFoundError` |
| update campo chave | `{"visitor_id": "x"}` | `ValueError` |
| update inválido | `{"status": "voando"}` | `ValueError` |
| update para `None` | `{"error": None}` com `error="x"` antes | `error is None` |
| turnos em ordem | `put_turn` 3, 1, 2 | `list_turns` → `[1, 2, 3]` |
| turno sobrescrito | `put_turn(1, "A")`, `put_turn(1, "B")` | um turno, texto `"B"` |
| turno sem sessão | `put_turn` com sessão inexistente | `SessionNotFoundError` |
| listar do visitante | 2 sessões de `local` (T0, T1) + 1 de `outro` | `[T1, T0]` só de `local` |
| concluídas por caso | 2 `completed` de `caso-a`, 1 `completed` de `caso-b`, 1 `ready` de `caso-a` | `list_completed("caso-a")` → 2; `list_completed()` → 3 |
| apagar | `delete_session` com 2 turnos | `get_session` e `list_turns` → `SessionNotFoundError` |
| apagar inexistente | `delete_session` sem sessão | `SessionNotFoundError` |

Específicos do DynamoDB (`test_repo_dynamo.py`):

| Caso | Entrada | Esperado |
| --- | --- | --- |
| ida e volta | `Session` com `overall_score=3.75`, `competency_scores`, `prompt_versions`, `ended_at` | `item_to_session(session_to_item(s)) == s`; item sem chaves `None`; floats como `Decimal` |
| turno completo | `Turn` com `decision` e `score` | ida e volta igual |
| datas | `created_at` UTC | item guarda string ISO |
| paginação | 30 turnos com página forçada pequena (`Limit`) | `list_turns` devolve 30 |
| erro inesperado | tabela que levanta `ClientError` de outro código | `RepositoryError` |
| protocolo | `isinstance(DynamoSessionRepository(...), SessionRepository)` | `True` |
