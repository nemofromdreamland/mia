# 4.4 — Build e push da imagem ARM64 para o ECR

Aprovação: modo autônomo pedido pelo dono.

## Contexto

O AgentCore Runtime (4.5) puxa a imagem do backend (Dockerfile ARM64 da 3.9) do ECR `mia-backend` criado na 4.1. Esta tarefa cria o script que faz build, login e push com a tag do commit. Fontes: TRD ("Infraestrutura": linha Container do backend; CI/CD item 2), plano 4.4.

## Requisitos

- R1. QUANDO o script roda, O SISTEMA DEVE usar como tag o hash curto do `HEAD` (12 caracteres); QUANDO há mudança não commitada em arquivo versionado, DEVE recusar com código 1 e mensagem clara (a tag tem de corresponder ao código da imagem). Arquivos não versionados não contam.
- R2. O SISTEMA DEVE executar, nesta ordem: `aws ecr get-login-password` (perfil `mia`, us-east-1) → `docker login` no registro da URL do repositório; `docker build --platform linux/arm64 -t <repo>:<tag> .`; `docker push <repo>:<tag>`.
- R3. A URL do repositório DEVE vir de `terraform -chdir=infra output -raw ecr_repository_url` (fonte única), ou do argumento `--repo`.
- R4. QUANDO `--dry-run`, O SISTEMA DEVE só imprimir os comandos, sem executar nenhum (nem o login).
- R5. QUANDO a tag já existe no ECR (tags imutáveis), O SISTEMA DEVE avisar e sair com 0 sem rebuild.

## Fora de escopo

- Push pelo CI/OIDC (4.8); apontar o runtime para a imagem (4.5); tag `latest` (o ECR é imutável e o runtime usa a tag do commit).

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |

| `scripts/push_image.py` | criar | funções abaixo + `main` com `--dry-run`, `--repo` |
| `tests/test_push_image.py` | criar | executor falso que grava os comandos |

**Interfaces**

```python
Runner = Callable[[list[str], str | None], str]   # (comando, stdin) -> stdout
def commit_tag(run: Runner) -> str: ...            # levanta DirtyTreeError
def repo_url(run: Runner, override: str | None) -> str: ...
def image_exists(run: Runner, repo: str, tag: str) -> bool: ...
def push_commands(repo: str, tag: str) -> list[list[str]]: ...   # build, push
def main(argv: Sequence[str] | None = None, run: Runner = ...) -> int: ...
```

**Decisões**

- Python em vez de `.sh` (desvio do nome no plano): roda igual no Windows do dono e no CI, e o executor injetável permite testar sem Docker/AWS (mesmo padrão de `scripts/build_proxy.py`).
- Senha do login vai por stdin (`--password-stdin`), nunca na linha de comando nem no log.
- `docker build --platform linux/arm64` (o Dockerfile já fixa a plataforma; no PC x86 roda sob emulação).

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| tag | `git rev-parse --short=12 HEAD` → `abc123def456` | tag `abc123def456` |
| sujo (erro) | `git status --porcelain --untracked-files=no` não vazio | `main` → 1, nenhum docker chamado |
| ordem | repo `123.dkr.ecr.us-east-1.amazonaws.com/mia-backend` | login → build arm64 → push, com `<repo>:<tag>` |
| senha | login | senha só no stdin do `docker login` |
| dry-run | `--dry-run` | 0 chamadas de aws/docker, comandos impressos |
| já existe | `describe-images` acha a tag | 0, sem build |
| repo por terraform | sem `--repo` | usa saída do `terraform output -raw` |

## Notas de implementação

- Passo 1: o executor recebe `(comando, stdin)` e devolve stdout. Um erro vira `CommandError` com no máximo 300 caracteres do stderr, nunca a senha. O `describe-images` com falha conta como "tag não existe". O dry-run real imprimiu os comandos `docker build --platform linux/arm64 -t <account-id>.dkr.ecr.us-east-1.amazonaws.com/mia-backend:<sha12> .` e `docker push ...`. O push real espera o ok do dono.
