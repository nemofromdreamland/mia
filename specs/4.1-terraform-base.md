# 4.1 — Terraform base

Aprovação: modo autônomo pedido pelo dono.

## Contexto

Primeira tarefa de infraestrutura: cria em Terraform (state local) os recursos sem os quais nada roda na AWS — as 3 tabelas DynamoDB, o bucket de dados, o repositório ECR, os parâmetros SSM, as roles IAM do runtime e da proxy e o alerta de Budget. Fontes: TRD ("Infraestrutura, deploy e CI/CD", "Segurança e LGPD", "Observabilidade e custo"), Backend Schema ("DynamoDB", "S3"). O código que consome isso já existe: `src/mia/repo_dynamo.py` (nomes de tabela e GSI fixos) e `src/mia/repo_s3.py`.

## Requisitos

- R1. QUANDO o `terraform plan` roda em `infra/`, O SISTEMA DEVE criar `mia-sessions` (PK `visitor_id` S, SK `session_id` S, GSI `by_case` com PK `case_id` S e SK `ended_at` S), `mia-turns` (PK `session_id` S, SK `turn_no` N) e `mia-meta` (PK `pk` S, SK `sk` S, TTL em `expires_at`), todas `PAY_PER_REQUEST`.
- R2. O SISTEMA DEVE criar o bucket `mia-data-<conta>` com Block Public Access total, criptografia SSE-S3, `BucketOwnerEnforced`, política que nega acesso sem TLS e regra de ciclo de vida que expira `sessions/` em 30 dias.
- R3. O SISTEMA DEVE criar o ECR `mia-backend` com tags imutáveis, scan on push e política de ciclo de vida que mantém só as 5 imagens mais novas.
- R4. O SISTEMA DEVE criar parâmetros SSM `SecureString` em `/mia/` para `GEMINI_API_KEY`, `GROQ_API_KEY`, `LANGFUSE_PUBLIC_KEY` e `LANGFUSE_SECRET_KEY` com valor provisório e `ignore_changes` no valor; nenhuma chave real NUNCA DEVE aparecer em `.tf`, `.tfvars` versionado ou state commitado.
- R5. O SISTEMA DEVE criar a role `mia-runtime` (confiança: `bedrock-agentcore.amazonaws.com` da própria conta) com só: CRUD nas 3 tabelas e índices; `Get/Put/DeleteObject` em `sessions/*` e `ListBucket` com prefixo `sessions/`; `bedrock:InvokeModel*` nos modelos/perfis de inferência usados; `bedrock:ApplyGuardrail`; leitura de `/mia/*` no SSM; pull no ECR `mia-backend`; logs e X-Ray.
- R6. O SISTEMA DEVE criar a role `mia-proxy` (confiança: `lambda.amazonaws.com`) com só logs básicos e `bedrock-agentcore:InvokeAgentRuntime` em runtimes `mia*` da conta.
- R7. O SISTEMA DEVE criar um Budget mensal de custo com alertas por e-mail (real em 50%, 80%, 100%; previsto em 100%), contando o uso antes dos créditos; o e-mail vem de variável, nunca do código versionado.
- R8. O código de `infra/` NUNCA DEVE declarar recurso cobrado por hora parada ou proibido no Free Plan (NAT Gateway, ALB/NLB, EC2, RDS, Organizations, Control Tower, Identity Center) — checado por teste.

## Fora de escopo

- `terraform apply` sem o "ok" do dono; backend remoto do state.
- API Gateway e Lambda (4.2), Guardrail (4.3), push de imagem (4.4), AgentCore Runtime (4.5), web (4.6), OIDC/CI (4.8).
- Carregar as chaves do SSM no container (o modo texto só usa Bedrock; fica para quando for preciso).
- CloudWatch Transaction Search e a chave KMS criados pela CLI na 0.7 (ver Decisões).

**Interfaces** (teste)

```python
def read_infra() -> str: ...               # concatena infra/*.tf
def resource_block(kind: str, name: str) -> str: ...  # texto do bloco `resource "<kind>" "<name>"`
```

**Decisões**

- GSI `by_case` com projeção `ALL` (desvio do Backend Schema, que lista atributos): `list_completed` converte o item do GSI direto em `Session`, que precisa de todos os campos. Custo de escrita extra irrelevante neste volume.
- Sem PITR nas tabelas e sem versionamento no bucket: dados de demo, retenção curta; evita custo.
- Valor provisório `"definir-no-console"` + `lifecycle { ignore_changes = [value] }`: o dono grava a chave real no console/CLI e o Terraform nunca a vê. KMS padrão `aws/ssm` (sem custo).
- Budget `COST` com `include_credit = false`: mostra o consumo real (que gasta os créditos), não o líquido ~0.
- Modelos do runtime: perfil de inferência `us.anthropic.claude-haiku-4-5-20251001-v1:0` (de `config/models.yaml`) + os foundation models que ele roteia (`us-east-1`, `us-east-2`, `us-west-2`).
- Permissão da proxy em `runtime/mia*` (e endpoints): o ARN real só existe na 4.5, que pode apertar.
- **Transaction Search / KMS da 0.7:** não gerenciados pelo Terraform. A chave KMS já está `PendingDeletion` (verificado com `aws kms describe-key`); o destino de spans do X-Ray está `XRay/ACTIVE` e é configuração da conta, não do MIA — fica como está e é registrado aqui, para a 4.5 decidir se o runtime manda traces.
- Testes de infra = regex no texto HCL + `terraform validate` (sem `python-hcl2`, para não criar dependência).
