# 3.9 — Container ARM64 do backend

Aprovação: modo autônomo pedido pelo dono.

## Contexto

O AgentCore Runtime roda containers ARM64 que respondem em `GET /ping` e `POST /invocations` na porta 8080 (TRD "Arquitetura" e "Infraestrutura"; confirmado no Gate 0, spec 0.7). A app FastAPI já tem as duas rotas (3.2), mas só existe uma montagem de dependências de desenvolvimento (`mia.api.dev`, tudo em memória, "nunca usado na AWS"). Falta: (1) o `ReportStore` em S3 previsto no Backend Schema ("S3": `sessions/<session_id>/report.json` e `summary.json`) e deixado fora da 3.3; (2) um ponto de entrada de produção que monta DynamoDB + S3 a partir do ambiente; (3) o `Dockerfile` ARM64.

## Requisitos

- R1. QUANDO `S3ReportStore.save(session_id, report, summary)` é chamado, O SISTEMA DEVE gravar `sessions/<session_id>/report.json` e `sessions/<session_id>/summary.json` no bucket configurado, em JSON do schema Pydantic.
- R2. QUANDO `S3ReportStore.load(session_id)` é chamado para uma sessão gravada, O SISTEMA DEVE devolver `(Report, CandidateSummary)` validados; para sessão sem relatório, DEVE levantar `SessionNotFoundError`; para outro erro do S3, `RepositoryError`.
- R3. QUANDO `S3ReportStore.delete(session_id)` é chamado, O SISTEMA DEVE remover os dois objetos (sem erro se não existirem).
- R4. QUANDO a mesma bateria de contrato roda contra `InMemoryReportStore` e `S3ReportStore` (moto), O SISTEMA DEVE passar igual nas duas.
- R5. QUANDO `mia.api.main` é importado com `MIA_STORAGE=memory`, O SISTEMA DEVE montar as dependências em memória (as mesmas da dev) e não tocar na AWS.
- R6. QUANDO `MIA_STORAGE=aws` (padrão), O SISTEMA DEVE montar `DynamoSessionRepository`, `DynamoMetaStore`, `DynamoCandidateCounter` e `S3ReportStore` com a região de `AWS_REGION` (padrão `us-east-1`) e o bucket de `MIA_DATA_BUCKET`; sem `MIA_DATA_BUCKET`, DEVE falhar na inicialização com mensagem clara.
- R7. QUANDO `MIA_STORAGE` tem outro valor, O SISTEMA DEVE falhar na inicialização com mensagem que lista os valores aceitos.
- R8. QUANDO a imagem é construída com `docker build --platform linux/arm64 -t mia-backend .`, O SISTEMA DEVE produzir uma imagem ARM64 com Python 3.12, dependências de produção do `uv.lock` (sem o grupo `dev`), `src/`, `prompts/`, `config/` e `cases/`, sem `.env`, `runs/`, `frontend/`, `tests/` nem `.venv/`.
- R9. QUANDO o container roda (`docker run -p 8080:8080 -e MIA_STORAGE=memory mia-backend`), O SISTEMA DEVE responder `GET /ping` → 200 `{"status": "Healthy"}` e `POST /invocations` com `{"action": "list_cases"}` → 200 com os 5 casos.

## Fora de escopo

- Terraform do ECR/S3/DynamoDB (4.1), push da imagem (4.4) e AgentCore (4.5).
- Credenciais dentro da imagem: na AWS vêm da role do runtime; localmente, do ambiente do `docker run`.
- WebSocket de voz (Fase 5) e Langfuse.
- Mudar regras do serviço ou do `ReportStore` (a interface fica igual).

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |

| `tests/test_repo_s3.py` | criar | R1–R4 com moto |

**Interfaces**

```python
# src/mia/repo_s3.py
DATA_PREFIX = "sessions"
class S3ReportStore:
    def __init__(self, client: Any, bucket: str) -> None: ...
    @classmethod
    def from_env(cls, *, bucket: str, region: str = "us-east-1") -> "S3ReportStore": ...
    def save(self, session_id: str, report: Report, summary: CandidateSummary) -> None: ...
    def load(self, session_id: str) -> tuple[Report, CandidateSummary]: ...
    def delete(self, session_id: str) -> None: ...

# src/mia/api/main.py
STORAGE_VALUES = ("aws", "memory")
def build_deps(env: Mapping[str, str]) -> ServiceDeps: ...
def build_app(env: Mapping[str, str] | None = None) -> FastAPI: ...   # None → os.environ
app: FastAPI   # lazily built? no: module-level, like dev.py
```

**Decisões**

- `S3ReportStore` num arquivo próprio (`repo_s3.py`), não em `repo_dynamo.py`: outro serviço, mesmo padrão (`client` injetável + `from_env`).
- Seleção por `MIA_STORAGE` (`aws` padrão, `memory` para teste local do container): permite o critério "docker run local responde" sem credenciais AWS. Na AWS, o Terraform (4.5) define `MIA_DATA_BUCKET`.
- `mia.api.dev` continua igual; `main.py` reaproveita `build_dev_deps()` no modo `memory`.
- Imagem base `python:3.12-slim` com `--platform=linux/arm64`; `uv` copiado da imagem oficial `ghcr.io/astral-sh/uv` (versão fixa); `uv sync --frozen --no-dev --no-install-project` em camada separada para cache.
- `CMD uvicorn mia.api.main:app --host 0.0.0.0 --port 8080` (porta do contrato do AgentCore).
- `runs/` é criado vazio no container (os `RunRecord`s são efêmeros lá; CloudWatch/Langfuse ficam para a Fase 4).
- Dependência `uvicorn` passa de transitiva do grupo dev para produção: é o servidor do container.

## Notas de implementação

- Passo 1: `S3ReportStore` em `repo_s3.py`, `client` injetável + `from_env`. Grava com `model_dump_json` e lê com `model_validate_json` (saída validada pelo schema). `NoSuchKey`/`404` → `SessionNotFoundError`; qualquer outro `ClientError` (ex.: bucket inexistente) → `RepositoryError`. `delete` usa um único `DeleteObjects` com as 2 chaves (S3 não reclama de chave ausente). Contrato roda com fixture parametrizada (memória e S3 via moto): 9 testes.
