# 2.6 — Métricas agregadas do conjunto A

## Contexto

A 2.5 roda o conjunto A no Promptfoo e checa item a item (schema, citações, ±1). Falta o número agregado que vai para o README e para as tabelas de comparação (2.7, 2.9): concordância juiz × humano, viés de verbosidade, consistência, JSON válido, custo e p95. Fontes: TRD "Avaliação" (divisão de trabalho: `evals/metrics.py` lê o JSON exportado), TRD "Observabilidade" (RunRecord é a fonte de custo/latência), PRD "Métricas de sucesso", BACKEND_SCHEMA "RunRecord".

## Requisitos

- R1. QUANDO receber pares (nota do juiz, nota humana) na escala 1–5, O SISTEMA DEVE calcular o kappa de Cohen com pesos quadráticos, o erro médio (juiz − humano, com sinal), o erro absoluto médio e a % de itens com |juiz − humano| ≤ 1.
- R2. QUANDO calcular a concordância, O SISTEMA DEVE reportá-la separada por split (`dev`, `test`, `todos`), destacando `test` como número oficial (PRD).
- R3. QUANDO houver itens `variant == "rambling"`, O SISTEMA DEVE reportar o viés de verbosidade = média de (juiz − humano) só nesses itens, com o n.
- R4. QUANDO houver itens `paraphrase` com `paraphrase_of`, O SISTEMA DEVE reportar a consistência entre paráfrases = média de |nota(paráfrase) − nota(original)| e a % de pares com nota igual.
- R5. QUANDO o mesmo `item_id` aparecer em mais de uma execução (repetições), O SISTEMA DEVE reportar a consistência entre execuções = média do desvio (máx − mín) da nota por item e a % de itens com nota idêntica em todas; com uma execução só, DEVE mostrar "n/d".
- R6. QUANDO ler o JSON exportado do Promptfoo, O SISTEMA DEVE reportar a % de citações verificáveis (itens que passaram em `assert_quotes_verified`) e contar itens com erro do provider ou saída fora do schema, excluindo-os das métricas de nota (com o n excluído mostrado).
- R7. QUANDO ler o JSONL de `runs/` do experimento, O SISTEMA DEVE reportar, por modelo e por prompt: % JSON válido na primeira tentativa (só registros com `json_valid_first_try` não `None`), custo total e médio em US$, latência p50 e p95 em ms e o n de chamadas.
- R8. QUANDO o export tiver mais de um provider (label), O SISTEMA DEVE gerar uma linha por modelo em cada tabela.
- R9. QUANDO executado pela CLI com o caminho do export, o(s) JSONL de runs e o nome do experimento, O SISTEMA DEVE gravar `results/<experimento>.md` com as tabelas em Markdown e um cabeçalho com data, arquivos de origem e n.
- R10. QUANDO uma métrica não tiver dados (n = 0, ex.: kappa com uma única categoria), O SISTEMA DEVE mostrar "n/d" em vez de lançar exceção ou dividir por zero.
- R11. QUANDO o arquivo de entrada não existir ou não for o formato esperado, O SISTEMA DEVE sair com código ≠ 0 e mensagem clara, sem gravar o `.md`.

**Interfaces**

```python
# evals/metrics.py
@dataclass(frozen=True)
class JudgedItem:
    item_id: str
    label: str                # provider label / modelo
    variant: str
    split: str | None
    paraphrase_of: str | None
    human_score: int | None
    judge_score: int | None   # None = erro do provider ou fora do schema
    quotes_ok: bool | None

@dataclass(frozen=True)
class Agreement:
    n: int
    weighted_kappa: float | None
    mean_error: float | None
    mean_abs_error: float | None
    pct_within_one: float | None

def weighted_kappa(judge: Sequence[int], human: Sequence[int], *, categories: Sequence[int] = (1, 2, 3, 4, 5)) -> float | None: ...
def agreement(items: Sequence[JudgedItem]) -> Agreement: ...
def verbosity_bias(items: Sequence[JudgedItem]) -> tuple[float | None, int]: ...
def paraphrase_consistency(items: Sequence[JudgedItem]) -> tuple[float | None, float | None, int]: ...
def repeat_consistency(items: Sequence[JudgedItem]) -> tuple[float | None, float | None, int]: ...
def percentile(values: Sequence[float], p: float) -> float | None: ...
def run_stats(records: Sequence[RunRecord]) -> list[RunStats]: ...   # agrupa por (model, prompt_name)

def load_promptfoo_export(path: Path) -> list[JudgedItem]: ...
def load_runs(paths: Sequence[Path], experiment: str | None) -> list[RunRecord]: ...
def render_report(experiment: str, items: Sequence[JudgedItem], records: Sequence[RunRecord], sources: Sequence[Path]) -> str: ...
def main(argv: Sequence[str] | None = None) -> int: ...
```

`RunStats` é um dataclass com `model, prompt_name, n, json_valid_pct, cost_total, cost_mean, p50_ms, p95_ms`. `RunRecord` vem de `mia.schemas`; `paraphrase_of` vem do `vars.item` (GoldenItem) do export.

CLI: `uv run python evals/metrics.py --export results/promptfoo_set_a.json --runs runs/2026-11-16_promptfoo_set_a.jsonl --experiment promptfoo_set_a` → grava `results/promptfoo_set_a.md`.

**Decisões**

- Kappa ponderado quadrático implementado em Python puro (matriz 5×5), sem `scikit-learn`/`numpy`: evita dependência nova; testado contra valores calculados à mão.
- Nota e metadata (`split`, `variant`, `human_score`) saem do export do Promptfoo (`response.output` + `response.metadata` + `vars.item`); custo, tokens, latência e JSON válido saem dos RunRecords, porque o export da 2.5 não traz custo/tokens (`tokenUsage` vem zerado).
- p95 pelo método "nearest-rank" (determinístico, fácil de explicar).
- Itens sem `human_score` ficam fora da concordância (todos os 70 têm nota hoje, mas a função não assume isso).
- Funções de métrica são puras e recebem listas; I/O só em `load_*` e `main`. Nenhuma chamada a LLM nesta tarefa.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| kappa perfeito | juiz = humano = [1,2,3,4,5] | 1.0 |
| kappa calculado à mão | juiz [1,2,3,4,5], humano [2,2,3,4,4] | valor fixo calculado no teste (tolerância 1e-6) |
| kappa sem variação | juiz = humano = [3,3,3] | `None` (n/d) |
| erro médio / ±1 | juiz [5,3,1], humano [4,3,3] | erro médio 0.0; MAE 1.0; ±1 = 66.7% |
| viés verbosidade | 2 rambling (juiz 4/hum 2, juiz 3/hum 2) + 1 level_5 | (1.5, 2) |
| sem rambling | só level_* | (None, 0) |
| paráfrase | par original=4, paráfrase=3; par 5/5 | média 0.5; iguais 50%; n 2 |
| repetição | item X em 3 execuções 3,4,3; item Y 5,5,5 | desvio médio 0.5; idênticos 50% |
| uma execução | cada item_id uma vez | (None, None, 0) → "n/d" |
| p95 | [100..2000 de 100 em 100] (20 valores) | 1900 |
| p95 vazio | [] | None |
| run_stats | 3 registros (1 com `json_valid_first_try=None`, 1 False, 1 True) | n 3; JSON válido 50% (base 2); custo somado |
| export com erro | resultado com `response.error` | `judge_score=None`, excluído e contado |
| export dois labels | fixture com 2 labels | agreement calculado por label (R8) |
| render | itens + runs pequenos | Markdown contém cabeçalhos "Concordância", "Viés de verbosidade", "Consistência", "Custo e latência" e "n/d" onde cabe |
| CLI arquivo ausente | `--export nao_existe.json` | código 1, mensagem, nenhum `.md` criado |
| CLI feliz | fixtures em `tmp_path` | código 0, arquivo `<experimento>.md` criado |
