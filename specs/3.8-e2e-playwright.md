# 3.8 — Teste E2E mínimo com Playwright

Aprovação: modo autônomo pedido pelo dono.

## Contexto

O Implementation Plan (3.8) pede um teste ponta a ponta no navegador: escolher caso → 2 respostas → encerrar → relatório → tela do recrutador, usando os `data-testid` da seção 14 do Design (`docs/design/README.md`, bloco 8). Os testes de tela (Vitest) mocam a API; este é o único teste que liga frontend real + backend real (`mia.api.dev`, repositórios em memória) + modelo real, e é a rede de segurança antes do deploy (Fase 4). Todos os `data-testid` da lista já existem no código (3.6a–3.6f).

## Requisitos

- R1. QUANDO o dono roda `npm run e2e` em `frontend/`, O SISTEMA DEVE subir sozinho o backend de dev (`uv run uvicorn mia.api.dev:app --port 8000`) e o Vite (`npm run dev`), rodar os testes no Chromium e derrubar os dois servidores no fim.
- R2. QUANDO o Início abre, O SISTEMA DEVE mostrar os 5 cards `case-card-{case_id}` dos casos de `cases/`.
- R3. QUANDO o teste escolhe um caso (`case-card-…` → `start-case`) e inicia (`start-interview`), O SISTEMA DEVE mostrar a primeira pergunta da MIA no `transcript`.
- R4. QUANDO o teste envia 2 respostas (`answer-input` + `send-answer`), O SISTEMA DEVE mostrar cada resposta e uma nova fala da MIA no `transcript` após cada envio.
- R5. QUANDO o teste encerra (`end-interview` → `confirm-end`), O SISTEMA DEVE mostrar o EndPanel e, quando a avaliação terminar, habilitar `view-feedback` ("Ver feedback"), que leva ao Relatório com `overall-score` visível.
- R6. QUANDO o teste vai ao recrutador (`recruiter-link`) e filtra pelo caso usado (`case-filter`), O SISTEMA DEVE listar ao menos uma `recruiter-row`; ao abri-la, DEVE mostrar `candidate-summary` e `next-step`.
- R7. QUANDO a tela do recrutador ou do candidato está aberta, O SISTEMA NÃO DEVE exibir o `visitor_id` do navegador (lido do `localStorage`) em nenhum texto da página.
- R8. QUANDO o dono roda `npm test` (Vitest), O SISTEMA NÃO DEVE executar os arquivos de `frontend/e2e/` (eles chamam modelo real e custam).

## Fora de escopo

- Rodar o E2E no CI (fica para a 4.8, se couber: precisa de credencial de modelo).
- Modelo falso/determinístico no backend de dev: o plano pede "modelo barato", e o Claude Haiku (padrão de `config/models.yaml`) é o modelo de desenvolvimento.
- Testes visuais (screenshot), acessibilidade automatizada, voz, Firefox/WebKit.
- Mudanças no backend ou nas telas (só se um `data-testid` faltar; não falta nenhum hoje).

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `frontend/package.json` | alterar | devDependency `@playwright/test`; scripts `e2e` e `e2e:install` |
| `frontend/playwright.config.ts` | criar | `testDir: "e2e"`, só Chromium, `webServer` com os 2 servidores, `baseURL` do Vite, timeouts longos |
| `frontend/vite.config.ts` | alterar | `test.exclude` inclui `e2e/**` (R8) |
| `frontend/e2e/flow.spec.ts` | criar | R2–R7 |
| `frontend/.gitignore` ou `.gitignore` | alterar | `test-results/`, `playwright-report/` |
| `frontend/tsconfig.node.json` | alterar se o lint/build pedir | incluir `playwright.config.ts` e `e2e/` |

**Interfaces**

```ts
// frontend/e2e/flow.spec.ts
test("Início lista os 5 casos", async ({ page }) => { ... })
test("candidato faz a entrevista e o recrutador vê o resultado", async ({ page }) => { ... })
async function sendAnswer(page: Page, text: string): Promise<void>
```

**Decisões**

- Dependência nova `@playwright/test` (dev): é a ferramenta citada no plano e no Design (bloco 8); só o Chromium é instalado (`npx playwright install chromium`).
- `webServer` com `reuseExistingServer: true`: se o dono já tiver os servidores no ar, o teste os reaproveita.
- Caso usado: `prompt-engineer-jr` (o do portfólio). Respostas fictícias, curtas e plausíveis, escritas no teste (sem dado real).
- Esperas por `data-testid`/texto, nunca `waitForTimeout`. Timeout de teste 5 min e de expect 90 s para o "Avaliando…" (judge + relatório no Haiku).
- Seletores só por `data-testid` da lista da seção 14 (mais `getByRole` quando o testid não existe, ex.: "Começar"/"Ver feedback" já têm testid).
- Backend de dev é em memória: cada execução começa sem sessões, então a única sessão concluída é a do teste (sem média; o recrutador lista todas as concluídas — regra atual de `list_recruiter_candidates` com < 3).

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| Início | abrir `/` | 5 elementos `[data-testid^=case-card-]` |
| Entrevista | caso `prompt-engineer-jr` → `start-case` → `start-interview` | ≥ 1 fala da MIA no `transcript` |
| 2 respostas | 2× `answer-input` + `send-answer` | cada texto visível no `transcript`; o número de falas da MIA cresce |
| Encerrar | `end-interview` → `confirm-end` | `view-feedback` com "Ver feedback" (≤ 90 s); clicar → `overall-score` |
| Recrutador | `recruiter-link` → `case-filter` = caso | ≥ 1 `recruiter-row`; abrir → `candidate-summary` e `next-step` |
| Privacidade | texto do `body` nas 2 telas do recrutador | não contém o `visitor_id` do `localStorage` |
| Vitest | `npm test` | nenhum arquivo de `e2e/` coletado |

## Notas de implementação

- Passo 1: `@playwright/test` como devDependency, só Chromium. `playwright.config.ts` sobe `uvicorn mia.api.dev:app` (cwd = raiz do repo, espera `/ping`) e o Vite em 5173 com `--strictPort`; `reuseExistingServer: true`. `tsconfig.node.json` passou a incluir a config e `e2e/` para o `tsc -b` checar os tipos. Vitest exclui `e2e/**` (27 arquivos, 218 testes, nenhum de `e2e/`). Saídas do Playwright no `.gitignore` da raiz.
- Passo 2: fluxo completo em `e2e/flow.spec.ts`. Falas da MIA contadas pela classe `fala` (tipografia da 2.4) dentro do `transcript`, já que não há testid por turno; cada envio espera a resposta aparecer e o número de falas da MIA crescer. O `visitor_id` é lido do `localStorage` (`mia:visitor_id`) e procurado no texto das duas telas do recrutador (R7). Desvio: o backend de dev precisa de região/perfil AWS; carregar o `.env` no teste foi recusado pela política de segurança, então o `webServer` passa `AWS_PROFILE=mia` e `AWS_REGION=us-east-1` (valores do AGENTS.md, sobrescrevíveis pelo ambiente). Rodada local: 2 passed em 34 s.
