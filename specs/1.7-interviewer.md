# 1.7 — Entrevistador (máquina de estados + ferramentas)

## Contexto

Durante a entrevista, cada resposta do candidato passa por uma máquina de estados determinística que decide o que é regra (tempo, limite de turnos e de aprofundamentos, qual é a próxima pergunta do plano) e só pergunta ao LLM rápido se vale aprofundar. O `interviewer.py` é esse núcleo, usado depois pela API (texto) e pela camada de voz (mesmas ferramentas). Fontes: TRD §Princípios (3), §Módulos (`interviewer.py`), §Orquestração; APP_FLOW §Fluxo 2 e §Fluxo 3; BACKEND_SCHEMA §`mia-sessions`/`mia-turns`, §Validações feitas pelo código, §Regras (30 turnos, 45 min, 4.000 caracteres); PRD RF-06.

## Requisitos

- R1. QUANDO a entrevista começar (`start`), O SISTEMA DEVE criar o estado com a primeira pergunta do plano como atual, `follow_ups_used = 0`, `turn_count = 1`, `started_at` = agora, e devolver o primeiro `Turn` (sem resposta, `is_follow_up = False`).
- R2. QUANDO uma resposta chegar, O SISTEMA DEVE rejeitar com `InterviewError` (sem chamar modelo) se o estado já estiver encerrado, se a resposta estiver vazia/só espaços ou se passar de 4.000 caracteres.
- R3. QUANDO uma resposta válida chegar, O SISTEMA DEVE mascará-la com `pii.mask_text` antes de qualquer chamada a LLM e gravar só o texto mascarado no turno.
- R4. QUANDO `time_check` rodar, O SISTEMA DEVE indicar fim se `turn_count >= max_turns` (padrão 30) ou se o tempo decorrido `>= max_minutes` (padrão: o menor entre `plan.estimated_minutes` + 3 de folga e 15; ver P1), e devolver os minutos restantes (nunca negativos).
- R5. QUANDO `time_check` indicar fim, O SISTEMA DEVE encerrar sem chamar `should_follow_up`, com motivo `time_or_turns`.
- R6. QUANDO não houver fim por tempo, O SISTEMA DEVE chamar `should_follow_up` (prompt `follow_up`, `ToolDecision`), passando pergunta, `look_for`, aprofundamentos restantes, minutos restantes, histórico e resposta mascarada.
- R7. QUANDO a decisão for `follow_up` e `follow_ups_used < 2`, O SISTEMA DEVE gerar um turno de aprofundamento com o `follow_up_text` da decisão, mesmo `question_id`, `is_follow_up = True`, e somar 1 em `follow_ups_used`.
- R8. QUANDO a decisão for `follow_up` mas `follow_ups_used >= 2`, ou `follow_up_text` vier vazio/nulo, O SISTEMA DEVE ignorar a decisão do LLM e tratar como `next_question` (o código decide), registrando a decisão original no turno respondido.
- R9. QUANDO a ação efetiva for `next_question` e houver pergunta seguinte no plano, O SISTEMA DEVE avançar para ela (`next_question`), zerar `follow_ups_used` e gerar o turno com o texto da pergunta.
- R10. QUANDO a ação efetiva for `next_question` sem pergunta seguinte, ou a decisão for `end`, O SISTEMA DEVE encerrar (`end_interview`) com motivo `plan_done`, gerando um turno final de despedida. QUANDO a decisão for `end` mas ainda houver pergunta no plano e tempo, O SISTEMA DEVE tratar como `next_question` (P2).
- R11. QUANDO o visitante pedir para encerrar (`end_interview` chamado de fora), O SISTEMA DEVE encerrar com motivo `visitor` sem chamar modelo.
- R12. QUANDO um turno for respondido, O SISTEMA DEVE disparar `score_answer` com (pergunta, resposta mascarada) por um avaliador injetado; uma falha do avaliador NÃO pode impedir a próxima fala (o turno fica com `score = None`).
- R13. QUANDO a fala do entrevistador for redigida, O SISTEMA DEVE usar um redator injetado (padrão: prompt `interviewer` v1); a pergunta, a fase e a instrução vêm do código, nunca do LLM.
- R14. QUANDO qualquer transição acontecer, O SISTEMA DEVE devolver um novo estado (o anterior não é alterado) e incrementar `turn_count` a cada turno novo.

## Fora de escopo

- `judge.py` e o prompt `judge` (tarefa 1.8): aqui o avaliador é só um parâmetro (`Scorer`).
- Persistência (repositórios, DynamoDB), API, cotas e status da sessão (`in_progress` → `scoring`).
- Execução realmente em segundo plano (thread/fila) do juiz: aqui a chamada é síncrona e protegida por try/except; a API decide como paralelizar.
- Camada de voz (Sonic) e fase `candidate_questions` interativa.
- Editar os prompts `follow_up`/`interviewer` v1.

**Interfaces**

```python
EndReason = Literal["plan_done", "time_or_turns", "visitor"]

class InterviewError(Exception): ...

class InterviewLimits(BaseModel):
    max_turns: int = 30
    max_follow_ups: int = 2
    max_answer_chars: int = 4000
    hard_max_minutes: int = 15
    slack_minutes: int = 3
    history_turns: int = 6

class InterviewState(BaseModel):          # frozen
    session_id: str
    plan: InterviewPlan
    current_index: int
    follow_ups_used: int
    turn_count: int
    started_at: datetime
    turns: list[Turn]
    ended: bool = False
    end_reason: EndReason | None = None

class TimeStatus(BaseModel):
    over: bool
    minutes_left: float

class StepResult(BaseModel):
    state: InterviewState
    answered: Turn          # turno respondido, com decision e score
    next_turn: Turn         # próxima fala (aprofundamento, pergunta ou encerramento)

Decider = Callable[[Question, str, InterviewState, TimeStatus], ToolDecision]
Writer = Callable[[Phase, str, str, list[Turn]], str]  # fase, pergunta, instrução, histórico → fala
Scorer = Callable[[Question, str], AnswerScore]
Clock = Callable[[], datetime]

# ferramentas
def time_check(state: InterviewState, now: datetime, limits: InterviewLimits) -> TimeStatus: ...
def next_question(state: InterviewState) -> Question | None: ...
def should_follow_up(question: Question, answer: str, state: InterviewState,
                     status: TimeStatus, **llm_options: Any) -> ToolDecision: ...  # prompt follow_up
def score_answer(scorer: Scorer, question: Question, answer: str) -> AnswerScore | None: ...
def end_interview(state: InterviewState, reason: EndReason, *, writer: Writer,
                  clock: Clock) -> tuple[InterviewState, Turn]: ...

# fluxo
def start(session_id: str, plan: InterviewPlan, *, writer: Writer, clock: Clock) -> tuple[InterviewState, Turn]: ...
def answer(state: InterviewState, text: str, *, decider: Decider, writer: Writer,
           scorer: Scorer, clock: Clock,
           limits: InterviewLimits = InterviewLimits()) -> StepResult: ...
def default_writer(**llm_options: Any) -> Writer: ...   # prompt interviewer v1 via prompts.run_prompt
```

**Decisões**

- **Máquina de estados em funções puras, sem LangGraph** (TRD §Orquestração): `answer` é a única função de transição; decisões externas (LLM, juiz, relógio) entram como callables injetados, o que permite testar todas as transições sem LLM.
- **O código tem a palavra final:** o `ToolDecision` do LLM é sugestão; limites (R5, R8) sobrescrevem. A decisão original fica gravada em `answered.decision` para auditoria/avaliação.
- **Pergunta do plano sai literal no turno?** O redator recebe a pergunta e a instrução; `Turn.interviewer_text` guarda a fala redigida e `question_id` liga ao plano. No aprofundamento, a "pergunta" passada ao redator é o `follow_up_text`.
- **Histórico para o LLM:** só turnos anteriores com respostas já mascaradas (`interviewer_text` + `answer_text`), como texto simples; tamanho limitado aos últimos N turnos (ver P4).
- **Tempo:** relógio injetado (`Clock`) e `datetime` com fuso UTC; nada de `datetime.now()` direto no núcleo.
- **Sem dependências novas.**

| Caso | Entrada | Esperado |
| --- | --- | --- |

| follow_up sem texto | `follow_up`, `follow_up_text None` | avança para `q2` |
| próxima pergunta | decider → `next_question` | `q2`, `follow_ups_used 0` |
| plano concluído | `next_question` em q4 | `ended True`, `end_reason "plan_done"`, turno final |
| LLM encerra cedo | decider → `end` em q1 | ignorado: avança para `q2` (P2) |
| LLM encerra no fim | decider → `end` em q4 | `ended True`, `"plan_done"` |
| tempo | plano de 10 min, relógio = início + 13 min | `ended`, `"time_or_turns"`, decider NÃO chamado |
| turnos | `turn_count == 30` | `ended`, `"time_or_turns"` |
| minutos restantes | início + 20 min | `minutes_left == 0` |
| visitante | `end_interview(state, "visitor")` | `ended`, nenhum modelo chamado |
| erro: encerrada | `answer` após `ended` | `InterviewError` |
| erro: vazia / longa | `"   "` / 4.001 chars | `InterviewError`, decider não chamado |
| PII | resposta com e-mail | decider, scorer e `answered.answer_text` recebem `[EMAIL]` |
| juiz falha | scorer levanta exceção | `answered.score None`, `next_turn` gerado normalmente |
| juiz ok | scorer devolve `AnswerScore` | `answered.score` preenchido |
| imutável | `answer(state, ...)` | `state` original inalterado |
| `should_follow_up` real | modelo falso devolve JSON `ToolDecision` | `ToolDecision` válido + 1 `RunRecord` do prompt `follow_up` |
| `default_writer` | modelo falso devolve texto | fala devolvida + `RunRecord` do prompt `interviewer` |

## Perguntas em aberto

- P1. Limite de tempo: usar `min(plan.estimated_minutes + folga, 45)` ou sempre 45 min? Qual folga? → resposta: entrevista curta, média de 10 a 15 min: limite = min(`estimated_minutes` + 3, 15). Os 45 min do BACKEND_SCHEMA continuam como teto da API; ajustar `estimated_minutes` dos casos/planner fica para as tarefas dos casos.
- P2. Na decisão `end` do LLM com perguntas ainda no plano, aceitar o encerramento ou forçar `next_question` (o código decide)? → resposta: o código decide: `end` com perguntas restantes e tempo vira `next_question`.
- P3. Turno final de encerramento: inclui "convite para perguntas do candidato" (APP_FLOW §Fluxo 3) ou só a despedida nesta tarefa? → resposta: só a despedida nesta tarefa.
- P4. Histórico enviado ao LLM: todos os turnos ou só os últimos N (ex.: 6)? → resposta: últimos 6 turnos (`history_turns`).
- P5. O turno de abertura/fala segue o redator LLM sempre, ou a primeira pergunta (fase `opening`) pode sair literal do plano para economizar uma chamada? → resposta: sempre pelo redator (fala consistente; uma chamada a mais no início).
- P6. A pergunta seguinte no plano é sempre a próxima da lista (ordem do plano) ou o código pula perguntas para caber no tempo restante? → resposta: sempre a ordem do plano; o fim por tempo cobre o resto.
