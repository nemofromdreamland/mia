# 3.1 — Camada de serviço com as 11 operações

## Contexto

A API (3.2) e o despachante do AgentCore precisam de uma única camada que aplique as regras do ciclo de vida da sessão, sem saber de HTTP. `service.py` expõe as 11 operações da tabela "API" do `docs/BACKEND_SCHEMA.md`, usa a interface de repositório e reaproveita `interviewer.py`, `report_graph.py` e `cases.py`. Fontes: BACKEND_SCHEMA (ciclo de vida, API, recrutador, erros).

## Requisitos

- R1. QUANDO `list_cases` for chamado, O SISTEMA DEVE devolver um `CaseSummary` por caso de `cases/`, com `completed_sessions` = número de sessões `completed` daquele caso.
- R2. QUANDO `create_session(visitor_id, case_id, mode)` for chamado com caso existente, O SISTEMA DEVE chamar o portão de cotas (`SessionGate`) antes de gravar qualquer coisa e criar a sessão em `ready` com `case_id`, `case_version`, `persona`, `language`, `job_title`, `fit_score` e `candidate_no` do caso, sem chamar modelo.
- R3. QUANDO `case_id` não existir (`invalid_input`) ou o portão recusar (`quota_exceeded` / `demo_paused`), O SISTEMA DEVE levantar o erro sem gravar nada nem avançar o contador.
- R4. QUANDO `list_sessions(visitor_id)` for chamado, O SISTEMA DEVE devolver só as sessões desse visitante, mais recentes primeiro.
- R5. QUANDO `get_session` for chamado, O SISTEMA DEVE devolver a `Session`; em `ready`, também o `Screening` e o `Case`; em `in_progress`, também `turns: list[PublicTurn]`. O plano nunca sai.
- R6. QUANDO a sessão não existir ou for de outro visitante, O SISTEMA DEVE levantar `ServiceError("not_found")` em todas as operações de sessão.
- R7. QUANDO `start_interview` for chamado em `ready`, O SISTEMA DEVE gerar o primeiro turno, passar a sessão para `in_progress` e devolver um `PublicTurn`; em outro status, `invalid_state`.
- R8. QUANDO `send_answer` for chamado fora de `in_progress`, O SISTEMA DEVE levantar `invalid_state`; com resposta vazia ou acima de 4.000 caracteres, `invalid_input`; com 30 turnos ou 45 minutos desde `started_at` já atingidos, `session_limit`. Nos três casos nada é gravado.
- R9. QUANDO `send_answer` for aceito e a entrevista continuar, O SISTEMA DEVE gravar os turnos e devolver o próximo `PublicTurn`; QUANDO a entrevista terminar (plano concluído ou limite do entrevistador), O SISTEMA DEVE gravar o turno de encerramento, rodar o relatório e devolver `{ended: true}`.
- R10. QUANDO `end_interview` for chamado em `in_progress`, O SISTEMA DEVE gravar o turno de despedida, passar por `scoring`, rodar o relatório e devolver `{status: "scoring"}`; fora de `in_progress`, `invalid_state`.
- R11. QUANDO o relatório for gerado com sucesso, O SISTEMA DEVE salvar `Report` e `CandidateSummary` no `ReportStore` e só então marcar `completed` com `overall_score`, `competency_scores` e `headline`.
- R12. QUANDO `get_report` for chamado em `completed`, O SISTEMA DEVE devolver `Report`, `Turn[]` completos e `is_above_case_avg`; em outro status, `invalid_state`.
- R13. QUANDO `delete_session` for chamado, O SISTEMA DEVE apagar a sessão, os turnos e o relatório; depois disso a sessão não aparece em nenhuma operação (inclusive nas do recrutador).
- R14. QUANDO qualquer operação devolver turnos antes de `completed`, O SISTEMA DEVE devolvê-los como `PublicTurn` (sem `score`, `decision`, `is_follow_up`).
- R15. QUANDO `list_recruiter_candidates(case_id | None)` for chamado, O SISTEMA DEVE devolver `CaseStats` por caso e as linhas `RecruiterCandidateRow` segundo as regras da "Tela do recrutador" (média só com ≥ 3, acima da média, ordenação).
- R16. QUANDO `get_recruiter_candidate(session_id)` for chamado para sessão `completed`, O SISTEMA DEVE devolver linha + `CandidateSummary` + `Report` + `Turn[]`; para sessão inexistente ou não `completed`, `not_found`. Nenhuma resposta do recrutador contém `visitor_id`.

## Fora de escopo

- REST, `/invocations`, `/ping` e JSON de erro (3.2).
- DynamoDB e S3 (3.3, 4.x): só interface + memória.
- Cotas reais, kill switch e validação de `X-Visitor-Id` (3.4): aqui só o protocolo `SessionGate` + "sempre permite".
- Contador atômico real de `candidate_no` (3.5): aqui contador em memória.
- `recruiter.py` com GSI `by_case` (3.10).
- Abandono por 2 h, voz, relatório assíncrono.

**Interfaces**

```python
# service.py
ErrorCode = Literal["not_found", "invalid_input", "invalid_state", "session_limit",
                    "quota_exceeded", "demo_paused", "llm_invalid_output",
                    "provider_unavailable", "internal"]

class ServiceError(Exception):
    def __init__(self, code: ErrorCode, message: str, *, retryable: bool = False) -> None: ...

class SessionGate(Protocol):
    def check(self, visitor_id: str) -> None: ...   # levanta ServiceError se recusar

class ServiceDeps(BaseModel):  # frozen, arbitrary_types_allowed
    repo: SessionRepository
    reports: ReportStore
    counter: CandidateCounter
    gate: SessionGate
    decider: Decider
    writer_for: Callable[[Persona], Writer]
    scorer: Scorer
    report: Callable[[InterviewPlan, list[Turn]], ReportResult]
    clock: Clock
    cases_dir: Path

def list_cases(deps: ServiceDeps) -> list[CaseSummary]: ...
def create_session(deps: ServiceDeps, visitor_id: str, case_id: str, mode: Mode) -> Session: ...
def list_sessions(deps: ServiceDeps, visitor_id: str) -> list[Session]: ...
def get_session(deps: ServiceDeps, visitor_id: str, session_id: str) -> SessionView: ...
def start_interview(deps: ServiceDeps, visitor_id: str, session_id: str) -> PublicTurn: ...
def send_answer(deps: ServiceDeps, visitor_id: str, session_id: str, answer_text: str) -> AnswerResult: ...
def end_interview(deps: ServiceDeps, visitor_id: str, session_id: str) -> dict[str, str]: ...
def get_report(deps: ServiceDeps, visitor_id: str, session_id: str) -> ReportView: ...
def delete_session(deps: ServiceDeps, visitor_id: str, session_id: str) -> None: ...
def list_recruiter_candidates(deps: ServiceDeps, case_id: str | None = None) -> RecruiterList: ...
def get_recruiter_candidate(deps: ServiceDeps, session_id: str) -> RecruiterCandidate: ...

def to_public(turn: Turn) -> PublicTurn: ...
def rebuild_state(session: Session, plan: InterviewPlan, turns: list[Turn]) -> InterviewState: ...

# repositories.py
class SessionRepository(Protocol):          # métodos novos
    def list_sessions(self, visitor_id: str) -> list[Session]: ...
    def list_completed(self, case_id: str | None = None) -> list[Session]: ...
    def delete_session(self, visitor_id: str, session_id: str) -> None: ...

class ReportStore(Protocol):
    def save(self, session_id: str, report: Report, summary: CandidateSummary) -> None: ...
    def load(self, session_id: str) -> tuple[Report, CandidateSummary]: ...
    def delete(self, session_id: str) -> None: ...

class CandidateCounter(Protocol):
    def next(self, case_id: str) -> int: ...

# schemas.py
class SessionView(BaseModel):
    session: Session
    case: Case | None = None
    screening: Screening | None = None
    turns: list[PublicTurn] | None = None

class AnswerResult(BaseModel):
    turn: PublicTurn | None = None
    ended: bool = False

class ReportView(BaseModel):
    report: Report
    turns: list[Turn]
    is_above_case_avg: bool | None    # None sem média (< 3 concluídas)

class RecruiterList(BaseModel):
    stats: list[CaseStats]
    candidates: list[RecruiterCandidateRow]

class RecruiterCandidate(BaseModel):
    row: RecruiterCandidateRow
    summary: CandidateSummary
    report: Report
    turns: list[Turn]
```

**Decisões**

- Funções com `deps` explícito, como em `simulation.py`; a 3.2 só traduz `ServiceError` em HTTP.
- O serviço é sem estado entre chamadas: o `InterviewState` é reconstruído a cada pedido a partir da `Session` (contadores, `current_question_id`, `started_at`), dos turnos salvos e do plano do fixture do caso (`load_case`). O plano nunca sai pela API.
- Limites do serviço (`session_limit`): 30 turnos e 45 min, checados antes de chamar o entrevistador. Os limites internos do entrevistador (fechamento educado por tempo do plano) continuam valendo e geram `{ended: true}`, não erro.
- Relatório síncrono dentro de `send_answer`/`end_interview`; falha → `scoring` + `error` e `llm_invalid_output` (pergunta 2).
- Erros: `SessionNotFoundError` → `not_found`; `SessionConflictError` → `invalid_state`; `InterviewError` → `invalid_input`; `CaseNotFoundError` → `invalid_input` em `create_session`.
- Recrutador: cálculo simples em `service.py` sobre `repo.list_completed`, seguindo as regras do Backend Schema; a 3.10 move para `recruiter.py` (pergunta 1).
- Sem dependências novas.

## Plano de testes

Fakes: writer fixo, decider configurável (`next_question`/`follow_up`/`end`), scorer devolve `AnswerScore(score=4,...)`, report devolve `ReportResult` fixo ou levanta `ReportError`, clock e gate controláveis; casos reais de `cases/`.

| Caso | Entrada | Esperado |
| --- | --- | --- |
| list_cases | 5 casos, 1 sessão `completed` no caso A | 5 `CaseSummary`; A com `completed_sessions=1` |
| create feliz | caso válido, gate permite | `Session` `ready`, `candidate_no=1`, 2ª sessão do caso → 2; report/writer chamados 0 vezes |
| create recusado | `case_id="xpto"`; ou gate levanta `quota_exceeded` | o erro certo; nada gravado; contador parado |
| list_sessions | 2 visitantes | cada um vê só as suas, mais recentes primeiro |
| get in_progress | após 1 resposta | `turns` são `PublicTurn`; JSON não contém `score`, `decision`, `is_follow_up` |
| outro visitante | `get_session(B, sessão de A)` | `not_found` (idem start/send/end/report/delete) |
| start | `ready`; de novo em `in_progress` | `PublicTurn` `turn_no=1`; depois `invalid_state` |
| send fora de estado | `ready`, `completed` | `invalid_state` |
| send vazio / 4.001 chars | `in_progress` | `invalid_input`; turnos inalterados |
| send limites | `turn_count=30`; ou clock = início + 45 min | `session_limit`; nada gravado |
| send continua | decider `next_question` | `AnswerResult.turn` = próximo `PublicTurn`; sem campos privados |
| send termina | resposta à última pergunta | `ended=True`; status `completed`; `ReportStore` tem o relatório |
| end feliz | `in_progress` | `{status: "scoring"}`; depois `get_session` → `completed` com `overall_score`, `headline` |
| end fora de estado | `ready` | `invalid_state` |
| relatório falha | report levanta `ReportError` | `llm_invalid_output` retryable; status `scoring` com `error`; turnos preservados |
| get_report antes | `in_progress` | `invalid_state` |
| get_report feliz | `completed` | `Report` + `Turn[]` com `score`; `is_above_case_avg=None` com < 3 sessões |
| delete | sessão `completed` | some de `get_session` (`not_found`), de `list_sessions` e do recrutador |
| recrutador < 3 | 2 `completed` | `average_score=None`; as 2 aparecem, `delta=None` |
| recrutador ≥ 3 | notas 2, 3, 4 | média 3; só a de 4 aparece, `delta=1.0` |
| recrutador anonimato | qualquer resposta | `"visitor_id"` não aparece no JSON |
| recrutador detalhe | sessão `in_progress` | `not_found` |

## Notas de implementação

- Passo 1: `list_sessions` ordena por `created_at` (desempate por `session_id`), mais recentes primeiro; `delete_session` de outro visitante → `SessionNotFoundError`; `ReportStore.load` sem relatório → `SessionNotFoundError` e `delete` é idempotente; tudo guarda cópias profundas.
- Passo 2: `create_session` valida o caso (`invalid_input`) ANTES do portão, para caso inexistente não gastar cota; depois portão → contador → gravação. `SessionGate` é `runtime_checkable` (o Pydantic exige) e `OpenGate` sempre permite. `get_session` só carrega fixtures em `ready`; `job_title` vem do `Screening`. Modelos de resposta já criados todos em `schemas.py`.
- Passo 3: o estado é reconstruído a cada chamada (`rebuild_state`); ordem das checagens do `send_answer`: estado → entrada → limites (30 turnos / 45 min), tudo antes de gravar. Quando o entrevistador encerra (`state.ended`), `send_answer` levanta `NotImplementedError` ANTES de gravar — o passo 4 troca isso por encerramento + relatório. `update_session` com `SessionConflictError` vira `invalid_state`.
- Passo 4: `_finish` é comum a `end_interview` e ao fim por `send_answer`: `scoring` (+`ended_at`) → relatório → turnos pontuados regravados → `ReportStore.save` → `completed`. `ReportError`/`LLMInvalidOutputError` deixam `scoring` + `error` e levantam `llm_invalid_output` retryable. No fim por `send_answer` os turnos são gravados antes do relatório, então ficam preservados. `get_report` devolve `is_above_case_avg=None` por enquanto; o passo 5 calcula.
