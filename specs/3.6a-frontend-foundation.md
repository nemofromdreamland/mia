# 3.6a — Fundação do frontend

## Contexto

Primeira parte da 3.6 (dividida em 3.6a–3.6f). Cria o projeto `frontend/` e tudo o que as 6 telas vão usar: tokens, fontes, shadcn ajustado, mascote, cabeçalho, toasts, cliente HTTP com `X-Visitor-Id`, mapeamento de erros, roteamento por status, polling e formatos. Fontes: Design seção 14 bloco 0, seções 2.4–2.9, 3.1–3.3, 4.3, 5 (estados comuns), 5.1, 5.22, 6 (cabeçalho), 7.1, 7.2, 9.1, 10.1, 13 (chaves do `localStorage`); Backend Schema "API" e "Erros e validação".

## Requisitos

- R1. QUANDO o projeto é instalado, O SISTEMA DEVE ter React + Vite + TypeScript em `frontend/`, com Tailwind v4, shadcn ("new-york", `neutral`, `cssVariables: true`) e as dependências da seção 3.1 do Design, e `npm run build`, `npm run lint` e `npm test` devem passar.
- R2. QUANDO a página carrega, O SISTEMA DEVE usar o `src/index.css` da seção 3.2 (tokens), as fontes da seção 2.4, `<html class="dark" lang="pt-BR">` fixo e as animações do `MiaMark` (seção 4.3), parando todas com `prefers-reduced-motion` exceto o `Loader2`.
- R3. QUANDO os componentes do shadcn são gerados, O SISTEMA DEVE aplicar os ajustes da seção 3.3 (variantes e tamanhos do botão, campos, diálogos, sonner, skeleton, badge e anel de foco de 2 px).
- R4. QUANDO `MiaMark` é renderizado sem `title`, O SISTEMA DEVE marcá-lo `aria-hidden`; com `title`, `role="img"` e `aria-label`; tamanhos ≤ 20 px usam o `viewBox` pequeno e não animam.
- R5. QUANDO uma tela do candidato (Início, Preparo, Relatório) usa o `AppHeader`, O SISTEMA DEVE mostrar o logotipo (link para `/`) e o link ghost "Ver como recrutador" (`ClipboardList`, `data-testid="recruiter-link"`, → `/recrutador`); nas telas do recrutador, "Simular uma entrevista" (`MessageSquare`, → `/`). Altura 56 px, borda inferior `border`; abaixo de `md` o link vira só ícone com `aria-label`.
- R6. QUANDO não existe `mia:visitor_id` válido (UUID v4) no `localStorage`, O SISTEMA DEVE gerar um com `crypto.randomUUID()` e guardar; sem `localStorage` disponível, o id vive só na memória da aba.
- R7. QUANDO o cliente HTTP faz uma chamada, O SISTEMA DEVE enviar `X-Visitor-Id` em toda requisição e, se a resposta for `invalid_input` por causa do header, gerar um id novo e repetir a chamada uma única vez.
- R8. QUANDO a API responde com erro no formato `{"error": {code, message, retryable}}`, O SISTEMA DEVE lançar um `ApiError` com `code`, `retryable` e `scope` (quando houver), nunca expondo a `message` crua na interface; erro de rede vira `ApiError` com código `network`; código desconhecido vira `internal`.
- R9. QUANDO uma tela pede a mensagem de um erro, O SISTEMA DEVE devolver o texto da seção 10.1 do Design para o par (código, contexto).
- R10. QUANDO `routeForStatus(status, id)` é chamado, O SISTEMA DEVE devolver a rota e o toast da seção 7.1 (`ready` → preparo; `in_progress` → entrevista; `scoring`/`completed` → relatório; `preparing`/`failed` → `/` + "Esta simulação não está disponível."; `abandoned` → `/` + "Esta simulação foi abandonada.").
- R11. QUANDO `usePolling` está ativo, O SISTEMA DEVE chamar a função a cada 2 s, pausar com a aba oculta, parar ao desmontar e, depois de 3 falhas de rede seguidas, passar a 5 s e expor `offline = true` até a primeira resposta boa (seção 7.2).
- R12. QUANDO um número ou data é formatado, O SISTEMA DEVE seguir a seção 9.1 (nota com 1 casa e vírgula, "N de 5", "N/100", datas `short`/`long` pt-BR, minutos inteiros, `mm:ss`).
- R13. QUANDO o app abre, O SISTEMA DEVE ter as rotas `/`, `/sessao/:id/preparo`, `/sessao/:id/entrevista`, `/sessao/:id/relatorio`, `/recrutador` e `/recrutador/:id` como esqueletos (H1 com o nome da tela e o cabeçalho certo; Entrevista sem `AppHeader`), título da aba "{Tela} · MIA" e o `Toaster` montado uma vez.
- R14. QUANDO o front roda em desenvolvimento, O SISTEMA DEVE encaminhar chamadas de `/api/*` para o backend local pelo proxy do Vite (sem CORS no backend); em build, a base vem de `VITE_API_BASE_URL`.

**Interfaces**

```ts
// lib/visitor.ts
export function getVisitorId(): string;
export function resetVisitorId(): string;          // gera e grava um novo
export function clearMiaStorage(): void;           // apaga todas as chaves mia:*
export function isUuidV4(value: string): boolean;

// lib/api.ts
export type ErrorCode =
  | "not_found" | "invalid_input" | "invalid_state" | "session_limit"
  | "quota_exceeded" | "demo_paused" | "llm_invalid_output"
  | "provider_unavailable" | "internal" | "network";
export class ApiError extends Error {
  code: ErrorCode; retryable: boolean; status: number | null; scope?: "visitor" | "global";
}
export function apiRequest<T>(method: "GET" | "POST" | "DELETE", path: string, body?: unknown): Promise<T>;

// lib/errors.ts
export type ErrorContext =
  | "any" | "interview_answer" | "session_screen" | "recruiter_candidate"
  | "interview" | "case_dialog" | "home";

export function errorMessage(error: ApiError, context: ErrorContext): ErrorPresentation;

// lib/routes.ts
export type SessionStatus =
  "preparing" | "ready" | "in_progress" | "scoring" | "completed" | "failed" | "abandoned";
export function routeForStatus(status: SessionStatus, id: string): { path: string; toast?: string };

// lib/format.ts
export function formatScore(value: number): string;        // 3.8 → "3,8"
export function formatAnswerScore(value: number): string;  // 4 → "4 de 5"
export function formatFit(value: number): string;          // 72 → "72/100"
export function formatDateShort(iso: string): string;      // "15/11/2026"
export function formatDateLong(iso: string): string;       // "15 de novembro de 2026"
export function formatMinutes(minutes: number): string;    // 18.4 → "18 min"
export function formatClock(seconds: number): string;      // 761 → "12:41"

// hooks/usePolling.ts
export function usePolling<T>(
  fn: () => Promise<T>,
  options: { enabled: boolean; onData: (data: T) => void },
```

**Decisões**

- Roteador: `react-router` (data router). Dependência nova: as 6 rotas com `:id` e `?caso=` exigem roteamento; é a opção padrão do ecossistema React.
- Testes: Vitest + `@testing-library/react` + `jsdom`. Dependências novas: o projeto exige testes primeiro e o Design não define ferramenta; Vitest usa a mesma config do Vite.
- O `scope` do `quota_exceeded` é lido do corpo do erro se o backend mandar; se não mandar, fica `undefined` (ver perguntas).
- Repetição por `invalid_input` só acontece quando a requisição foi feita com um id que o próprio front considera inválido ou quando a API recusa o header; não repete `invalid_input` de corpo (ex.: resposta longa) — distinguido pelo contexto da chamada (ver perguntas).
- Proxy do Vite em vez de CORS: nada muda no backend nesta tarefa.
- Fontes, cores e textos copiados do Design sem alteração; nenhum hex fora de `index.css`, `MiaMark` e `favicon.svg`.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| visitor novo | `localStorage` vazio | gera UUID v4 e grava em `mia:visitor_id` |
| visitor existente | id válido salvo | devolve o mesmo id |
| visitor inválido | `"abc"` salvo | gera um novo |
| sem storage | `localStorage` lança erro | devolve id e mantém em memória |
| limpar | chaves `mia:visitor_id`, `mia:draft:1`, `outra` | só `outra` sobra |
| header enviado | `apiRequest("GET","/cases")` | `fetch` recebe `X-Visitor-Id` |
| retry header | 1ª resposta 422 `invalid_input`, 2ª 200 | 2 chamadas, ids diferentes, devolve o corpo |
| retry só 1 vez | 422 duas vezes | lança `ApiError` `invalid_input` após 2 chamadas |
| erro da API | 503 `demo_paused` | `ApiError{code:"demo_paused", retryable:false}` |
| código desconhecido | `{"error":{"code":"xyz"}}` | `code: "internal"` |
| rede | `fetch` rejeita | `code: "network"` |
| 204 | `DELETE` | resolve `undefined` |
| mensagem | `quota_exceeded` scope `visitor`, `case_dialog` | "Você já fez 5 simulações hoje. Volte amanhã para fazer mais." |
| mensagem | `invalid_state`, `any` | toast "Esta simulação mudou de etapa. Atualizando…" |
| mensagem | `internal` com `retryable` | toast com `retry: true` |
| rotas | cada um dos 7 status | rota/toast da seção 7.1 |
| formatos | 3.8, 4, 72, `2026-11-15T10:00:00Z`, 18.4, 761 | "3,8", "4 de 5", "72/100", "15/11/2026", "15 de novembro de 2026", "18 min", "12:41" |
| polling | timers falsos, 3 ciclos | `fn` chamada a cada 2 s |
| polling oculto | `document.hidden = true` | nenhuma chamada |
| polling offline | 3 falhas de rede | `offline = true`, próximo ciclo em 5 s; sucesso → `offline = false` |
| MiaMark | sem/com `title`; `size=20` | `aria-hidden` / `role="img"`; `viewBox="14 12 72 72"` |
| AppHeader | `role="candidate"` / `"recruiter"` | link "Ver como recrutador" com `data-testid` / "Simular uma entrevista" |
| rotas do app | `/sessao/x/entrevista` | esqueleto sem `AppHeader`; título da aba "Entrevista · MIA" |

## Perguntas em aberto

- Dependências novas não listadas no Design: `react-router`, `vitest`, `@testing-library/react`, `@testing-library/jest-dom`, `jsdom`. Aprova? → resposta: aprovadas (dono pediu modo autônomo em 16/11; decisão pela recomendação).
- O erro `quota_exceeded` do backend traz o `scope` (`visitor`/`global`)? O formato único do Backend Schema não tem esse campo. Se não trouxer, a 3.6a usa a mensagem de `visitor` como padrão e abrimos a questão no backend? → resposta: o backend não manda `scope` hoje. O front lê `scope` se vier; sem ele, usa a mensagem de `visitor`. Sem mudança no backend nesta tarefa.
- Como saber se um `invalid_input` foi do header (repete com id novo) ou do corpo (não repete)? Proposta: repetir só quando o código for `invalid_input` e a chamada não tiver corpo ou o caminho não for `/turns`. → resposta: aprovada a proposta: repete só se o caminho não terminar em `/turns`.
- Não existe comando para subir a API local (`create_app` exige `ServiceDeps`). As telas 3.6b–3.6f precisam disso; entra como tarefa de backend antes da 3.6b? → resposta: entra como primeiro passo da spec 3.6b (script de dev com repositório em memória), registrado como desvio.

## Notas de implementação

- Passo 1: template `react-ts` do Vite 6; `.gitignore` do próprio template cobre `node_modules`/`dist` (raiz não alterada); `npm test` = `vitest run`.
- Passo 2: o CLI atual do shadcn não aceita mais `-b neutral`; `components.json` escrito à mão ("new-york", `neutral`). O `add` importou `cn` de um pacote npm homônimo: removido, criado `src/lib/utils.ts` (clsx + tailwind-merge) e removido `next-themes` (tema fixo). Variantes `secondary`/`xs`/`icon-*` do botão removidas (não existem no Design). Regra `react-refresh/only-export-components` desligada só em `components/ui/`.
- Passo 3: base da API = `VITE_API_BASE_URL` ou `/api` (proxy). Erro sem JSON ou com código desconhecido → `internal` com `retryable: true`. `invalid_input` fora de `/turns` → toast de `internal` (o retry com id novo já falhou).
- Passo 4: `usePolling` usa uma cadeia de `setTimeout` (primeira chamada após 2 s); só erro `network` conta como falha para o modo offline.
- Passo 5: títulos das abas: Início "Suas simulações", Preparo, Entrevista, Relatório, Recrutador "Candidatos", Candidato (o "Candidato {n}" entra na 3.6f). Logotipo usa `text-[20px] tracking-[0.02em]` porque a seção 2.9 fixa esses valores e não há token equivalente. `TooltipProvider` envolve o app (exigência do shadcn).
