# 4.5 — AgentCore Runtime + endpoint

Aprovação: modo autônomo pedido pelo dono.

## Contexto

Põe o container do backend (3.9, imagem no ECR pela 4.4) para rodar no AgentCore Runtime, com autenticação IAM (SigV4), e liga a Lambda proxy (4.2) a ele. Fontes: TRD ("Arquitetura"; "Infraestrutura": linha Runtime do agente; "Segurança": a proxy só invoca o runtime), Backend Schema ("API": contrato `/invocations`), plano 4.5. Role de execução `mia-runtime` vem da 4.1.

## Requisitos

- R1. O SISTEMA DEVE criar `aws_bedrockagentcore_agent_runtime` `mia_backend` com a imagem `<ecr>:<image_tag>`, role `mia-runtime`, rede `PUBLIC`, protocolo `HTTP` e env `MIA_STORAGE=aws`, `MIA_DATA_BUCKET=<bucket da 4.1>`, `AWS_REGION=<região>`; sem `authorizer_configuration` (o padrão é IAM/SigV4).
- R2. O SISTEMA DEVE criar o endpoint `live` apontando para a versão atual do runtime.
- R3. O SISTEMA DEVE anexar ao runtime uma política de recurso que permite `bedrock-agentcore:InvokeAgentRuntime` só à role `mia-proxy` e NEGA essa ação a qualquer outro principal (`aws:PrincipalArn` diferente da role da proxy).
- R4. A Lambda proxy DEVE receber `AGENT_RUNTIME_ARN` = ARN do runtime e `AGENT_RUNTIME_QUALIFIER = live`; a política IAM da proxy DEVE se restringir a esse runtime e seus endpoints (sai o curinga `runtime/mia*` da 4.1).
- R5. QUANDO o navegador chama `GET /cases` pela URL do API Gateway com `X-Visitor-Id` válido, a resposta DEVE ser 200 com os 5 casos (a proxy invoca o runtime com sucesso).
- R6. QUANDO alguém chama o endpoint do runtime sem SigV4 (ex.: `curl` direto), ou com credenciais IAM que não são da proxy, a chamada DEVE ser recusada (403 / `AccessDeniedException`).

## Fora de escopo

- WebSocket/voz (Fase 5), Transaction Search/OTEL (mantido como está, ver 4.1), VPC, Plano B (o Gate 0 passou).
- Carregar segredos do SSM no container (o modo texto só usa Bedrock).

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `infra/agentcore.tf` | criar | runtime, endpoint `live`, política de recurso |
| `infra/variables.tf` | alterar | `image_tag` (sem padrão); sai `agent_runtime_arn` |
| `infra/lambda.tf` | alterar | env da proxy vindo do runtime/endpoint |
| `infra/iam.tf` | alterar | política da proxy restrita ao ARN do runtime |
| `infra/outputs.tf` | alterar | `agent_runtime_arn` |
| `tests/test_infra.py` | alterar | R1–R4 |

**Decisões**

- Nome `mia_backend` (o AgentCore não aceita hífen); o ARN `runtime/mia_backend-<sufixo>` cabe na política da 4.1 até o passo 2 apertá-la.
- `image_tag` vem do `terraform.tfvars` local (e de `-var` no CI): imagem imutável por commit, troca explícita.
- Endpoint próprio `live` em vez do `DEFAULT` implícito: o TRD pede "runtime + endpoint" e fica claro qual versão está no ar.
- Negação explícita na política de recurso: sem ela, qualquer usuário IAM da conta com permissão ampla (ex.: `mia-dev`) também invocaria.

## Critérios de aceite

- [ ] Proxy invoca com sucesso — `curl -H "X-Visitor-Id: <uuid4>" <api_url>/cases` → 200 com 5 casos
- [ ] Chamada sem SigV4 é recusada — `curl -X POST https://bedrock-agentcore.us-east-1.amazonaws.com/runtimes/<arn-codificado>/invocations` → 403
- [ ] Credencial que não é da proxy é recusada — `aws bedrock-agentcore invoke-agent-runtime ... --profile mia` → AccessDenied
- [ ] `apply` revisado pelo dono
- [ ] `uv run pytest` e `uv run ruff check .` passam
