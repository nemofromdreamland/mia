# 3.6c — Tela Preparo

## Contexto

Bloco 2 da seção 14 do Design: a tela `/sessao/:id/preparo` mostra quem o visitante vai interpretar e a triagem do caso, e inicia a entrevista. Fontes: `docs/design/05-telas.md` (6.4), `04-componentes.md` (5.15, 5.16, 5.19, 5.24), `06-fluxos-voz-regras.md` (7.1/7.2 via `routeForStatus`), `07` (10.1, 13), `BACKEND_SCHEMA` (`SessionView`, `Case`, `Screening`, `PublicTurn`).

## Requisitos

- R1. QUANDO a tela abre, O SISTEMA DEVE chamar `GET /sessions/:id` e mostrar um skeleton com o formato da triagem até a resposta.
- R2. QUANDO a sessão está `ready`, O SISTEMA DEVE mostrar: rótulo "TRIAGEM · VISÃO DO RECRUTADOR", `h1` com `screening.job_title`, a linha "{company} · {Entrevista técnica} com a MIA · cerca de {estimated_minutes} min (máximo 45) · {Texto|Voz}", o bloco "VOCÊ VAI INTERPRETAR" com `candidate_blurb`, FitScore, "Pontos fortes" e "Pontos de atenção" (cada um com o `point` e um EvidenceQuote "DO CV DO CASO"), as palavras-chave ausentes, "O que será avaliado" (lista numerada de `competencies`) e "As perguntas só aparecem durante a entrevista.".
- R3. QUANDO `missing_keywords` está vazio, O SISTEMA DEVE esconder essa seção.
- R4. O FitScore DEVE mostrar "{n}" em `text-display` + "/100", barra de 240×4 px com marcas em 40 e 70, rótulo "Aderência baixa/média/alta" (0–39/40–69/70–100) e `role="meter"` com `aria-valuetext="72 de 100, aderência alta"`.
- R5. O KeywordChip DEVE ser `font-mono text-small`, borda `border-strong`, raio 6 px, não clicável.
- R6. QUANDO o visitante clica "Começar entrevista" (`data-testid="start-interview"`), O SISTEMA DEVE chamar `POST /sessions/:id/start`, mostrar "Iniciando…" com `Loader2` (`aria-busy`) e, ao receber o `PublicTurn`, navegar para `/sessao/:id/entrevista`.
- R7. QUANDO o visitante clica "Voltar" (outline), O SISTEMA DEVE navegar para `/`.
- R8. QUANDO a sessão não está `ready`, O SISTEMA DEVE redirecionar com `routeForStatus` (com o toast, se houver).
- R9. QUANDO a API devolve `not_found`, O SISTEMA DEVE mostrar a tela inteira "Simulação não encontrada" / "Ela pode ter sido apagada." + "Voltar ao início".
- R10. QUANDO o `start` falha com `invalid_state`, O SISTEMA DEVE mostrar o toast da 10.1, recarregar a sessão e redirecionar por `routeForStatus`; outros erros viram toast pela `errorMessage` e o botão volta ao normal.
- R11. QUANDO `mode` é `voice`, O SISTEMA DEVE mostrar acima dos botões o InlineNotice `neutral` "Use fone de ouvido para a MIA não ouvir a própria voz.".
- R12. QUANDO o `GET` falha com outro erro, O SISTEMA DEVE mostrar InlineNotice `danger` com o texto da `errorMessage` e "Tentar de novo".

## Fora de escopo

- Pedido de microfone e modo voz real (tarefa Voz); `PrepSteps` (só CLI).
- Estados da seção 10.2 (offline, demora) — tarefa 3.7.

**Interfaces**

```ts
// lib/types.ts
export type Evidence = { point: string; cv_quote: string };
export type Screening = { job_title: string; fit_score: number; strengths: Evidence[]; concerns: Evidence[];
  missing_keywords: string[]; competencies: string[] };
export type Case = { case_id: string; title: string; company: string; level: Level; persona: Persona;
  language: Language; blurb: string; candidate_blurb: string; estimated_minutes: number; version: number };
export type PublicTurn = { turn_no: number; question_id: string; interviewer_text: string;
  answer_text: string | null; created_at: string };
export type SessionView = { session: Session; case: Case | null; screening: Screening | null; turns: PublicTurn[] | null };

// components
export function fitLabel(score: number): string;
export function FitScore(p: { score: number }): JSX.Element;
export function EvidenceQuote(p: { label: string; quote: string; source?: string; verified?: boolean | null }): JSX.Element | null;
export function KeywordChip(p: { children: string }): JSX.Element;
export function SessionNotFound(): JSX.Element;

// hooks/useSessionView.ts
type ViewState = { state: "loading" } | { state: "not_found" } | { state: "error"; error: ApiError }
  | { state: "ready"; view: SessionView };
export function useSessionView(id: string, expected: SessionStatus[]): { view: ViewState; reload: () => Promise<void> };
```

**Decisões**

- `EvidenceQuote` aplica a regra da 5.16 quando recebe `source` (`source.includes(quote)`) e `verified !== false`. No Preparo o CV não chega ao front; o `cv_quote` já foi verificado por código ao gerar o fixture, então é mostrado sem `source`.
- `useSessionView` redireciona (com `routeForStatus`) quando o status não está em `expected`; as próximas telas reutilizam o hook.
- Relógio da linha de meta: ícone `Clock` 16 px do lucide (2.7) antes de "cerca de".
- Rótulos das seções "Pontos fortes"/"Pontos de atenção" em `h2`, duas colunas a partir de `md`.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| FitScore | 72 / 39 / 40 | "72" + "/100", "Aderência alta"; "Aderência baixa"; "Aderência média"; meter com `aria-valuenow` |
| EvidenceQuote ok | quote presente em `source` | `<mark>` com “quote” e rótulo |
| EvidenceQuote ausente / `verified=false` | — | não renderiza nada |
| carregando | GET pendente | skeleton (`prep-skeleton`) |
| pronto | `SessionView` ready | h1, meta, interpretar, 72/100, "DO CV DO CASO", chips, competências numeradas |
| sem keywords | `missing_keywords: []` | título da seção ausente |
| começar | clique `start-interview` | POST `/start`; "Iniciando…"; navega para `/entrevista` |
| start `invalid_state` | 409 | toast "Esta simulação mudou de etapa. Atualizando…" e redireciona |
| start erro `internal` | 500 | toast, botão volta a "Começar entrevista" |
| status `in_progress` | GET | vai para `/entrevista` |
| status `failed` | GET | vai para `/` com toast "Esta simulação não está disponível." |
| `not_found` | 404 | "Simulação não encontrada" + "Voltar ao início" |
| voz | `mode: voice` | aviso do fone de ouvido |
| erro no GET | 500 | InlineNotice com "Tentar de novo" que repete o GET |
