# 1.6 — Grafo de preparação (prep_graph)

## Contexto

Antes da entrevista, o MIA precisa de uma triagem (`Screening`) e de um plano (`InterviewPlan`). O `prep_graph.py` é o grafo LangGraph que faz isso: extrair o texto do CV → mascarar PII → triagem → plano → validar cobertura. Ele é usado offline para gerar as fixtures dos casos (`scripts/build_cases.py`, tarefa futura) e pela CLI. Fontes: TRD §Módulos (linha de `prep_graph.py`), TRD §Avaliação conjunto C, BACKEND_SCHEMA §Preparação, CASES §Como as fixtures são geradas, PRD RF-04/métrica "Qualidade do plano".

## Requisitos

- R1. QUANDO o CV for um arquivo `.pdf`, O SISTEMA DEVE extrair o texto de todas as páginas, na ordem.
- R2. QUANDO o CV for `.md` ou `.txt`, O SISTEMA DEVE ler o texto em UTF-8 sem conversão.
- R3. QUANDO a extensão não for `.pdf`/`.md`/`.txt`, ou o texto extraído estiver vazio (só espaços), O SISTEMA DEVE levantar `PrepError` com mensagem que cite o arquivo, sem chamar modelo.
- R4. QUANDO o texto do CV for obtido, O SISTEMA DEVE aplicar `pii.mask_cv` ao CV e `pii.mask_text` à vaga ANTES de qualquer chamada a LLM; nenhuma chamada recebe o texto original.
- R5. QUANDO a triagem rodar, O SISTEMA DEVE usar o prompt `screening` (v2 por padrão, ver P6) via `llm.invoke_structured` e obter um `Screening` validado.
- R6. QUANDO a triagem voltar, O SISTEMA DEVE conferir com `checks.unverified_quotes` que todo `cv_quote` de `strengths` e `concerns` existe literalmente no CV mascarado; citações não encontradas entram na lista de problemas de validação.
- R7. QUANDO o plano rodar, O SISTEMA DEVE usar o prompt `planner` (v2 por padrão, ver P6) com a vaga mascarada, a triagem serializada em JSON, `persona`, `level` e `estimated_minutes`, e obter um `InterviewPlan` validado.
- R8. QUANDO o plano voltar, O SISTEMA DEVE validar cobertura de forma determinística (código, não LLM): (a) cada item de `screening.competencies` aparece como `competency` de pelo menos 1 pergunta; (b) pelo menos 1 pergunta tem `targets_concern` preenchido; (c) `plan.persona` é igual à persona pedida; (d) ids das perguntas são únicos.
- R9. QUANDO houver qualquer problema de validação (R6 ou R8), O SISTEMA DEVE levantar `PrepValidationError` com a lista de todos os problemas (não só o primeiro) e com o `Screening` e o `InterviewPlan` obtidos anexados, para inspeção.
- R10. QUANDO não houver problemas, O SISTEMA DEVE devolver `PrepResult(screening, plan)`.
- R11. QUANDO o grafo rodar, O SISTEMA DEVE gravar exatamente 2 `RunRecord` (triagem e plano), com o mesmo `session_id`/`experiment` recebidos (herdado de `invoke_structured`).
- R12. QUANDO a saída do modelo for inválida mesmo após o reparo, O SISTEMA DEVE propagar `LLMInvalidOutputError` sem rodar os nós seguintes.

**Interfaces**

```python
# src/mia/prompts.py
def run_prompt_structured[T: BaseModel](

) -> T: ...

# src/mia/prep_graph.py
class PrepError(Exception): ...

class PrepValidationError(PrepError):
    problems: list[str]
    screening: Screening | None
    plan: InterviewPlan | None

class PrepInput(BaseModel):
    cv_path: Path
    job_text: str

class PrepState(TypedDict, total=False):
    input: PrepInput
    cv_text: str
    cv_masked: str
    job_masked: str
    screening: Screening
    plan: InterviewPlan
    problems: list[str]

def extract_cv_text(path: Path) -> str: ...                       # R1–R3
def check_screening_quotes(screening: Screening, cv_masked: str) -> list[str]: ...  # R6
def check_plan_coverage(
    screening: Screening, plan: InterviewPlan, persona: Persona
) -> list[str]: ...                                                # R8
def build_prep_graph(
    *,
    model: str | None = None,
    experiment: str | None = None,
    session_id: str | None = None,
    runs_dir: Path = DEFAULT_RUNS_DIR,
    chat_model: BaseChatModel | None = None,
    screening_version: int = 2,
    planner_version: int = 2,
) -> CompiledStateGraph: ...
def run_prep(data: PrepInput, **graph_options: Any) -> PrepResult: ...   # R9, R10
```

Nós (funções privadas, uma por etapa): `_extract` → `_mask` → `_screen` → `_plan` → `_validate`, ligados em linha reta (`START → … → END`).

**Decisões**

- **Dependências novas:** `langgraph` (exigido pelo TRD para a preparação; mesmo ecossistema LangChain já instalado) e `pypdf` (extração de texto pura em Python, sem binários nativos, leve). Nenhuma das duas importa SDK de provedor; o teste de arquitetura existente continua valendo.
- **Grafo linear, sem laço:** cada nó é uma função pura sobre o estado, testável isolada. A validação junta problemas em `state["problems"]`; `run_prep` decide levantar `PrepValidationError` (o código decide, não o LLM).
- **Validação só do que é verificável:** citação literal (R6) e cobertura estrutural (R8). "Perguntas mirando a lacuna" vira a regra (b) `targets_concern`; a qualidade disso fica para o conjunto C.
- **Triagem em JSON para o planner:** `screening.model_dump_json(indent=2)` — o prompt `planner` v1 espera texto.
- **Modelo falso nos testes:** reaproveita o padrão de `test_llm.py` (respostas em sequência); nenhum teste chama provedor real.
- **PDF de fixture:** gerado uma vez por um helper de teste que escreve um PDF mínimo com texto (sem dependência nova) e commitado — ver P3.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| PDF feliz | `cv_ficticio.pdf` (2 páginas) | texto contém frases das 2 páginas, na ordem |
| md/txt | `cv.md` UTF-8 com acento | texto idêntico ao arquivo |
| extensão inválida | `cv.docx` | `PrepError` citando o arquivo |
| PDF vazio | PDF sem texto | `PrepError`, 0 chamadas ao modelo |
| mascaramento | CV com e-mail/telefone/nome | `input` dos 2 RunRecords não contém nenhum valor pessoal; contém `[EMAIL]` |
| feliz completo | PDF + vaga + respostas `screening_ok`/`plan_ok` | `PrepResult` válido; 2 linhas em `runs/*.jsonl` com `prompt_name` screening e planner |
| citação inventada | triagem com `cv_quote` que não está no CV | `PrepValidationError`, problema cita a citação |
| competência sem pergunta | plano sem pergunta para 1 competência | problema cita a competência |
| sem lacuna | nenhuma pergunta com `targets_concern` | problema sobre lacuna |
| persona trocada | pediu `technical`, plano `hr` | problema sobre persona |
| ids repetidos | 2 perguntas `q1` | problema sobre id |
| vários problemas | citação + competência | `problems` com os 2 |
| saída inválida | triagem quebrada 2 vezes | `LLMInvalidOutputError`; planner não é chamado |
| `run_prompt_structured` | prompt de fixture + modelo falso | instância do schema; RunRecord com nome/versão do prompt |
