# 1.4 — pii.py: mascaramento de dados pessoais

## Contexto

Todo texto que o visitante digita (web) e o CV da CLI precisa ter dados pessoais mascarados antes de ser salvo ou enviado a um modelo (PRD RF-07, RNF-03; TRD §módulos `pii.py`, §segurança; BACKEND_SCHEMA "Convenções"). Esta tarefa cria só o módulo puro `texto → texto mascarado`; ligá-lo ao `prep_graph`, à API e à CLI fica para as tarefas que criam esses fluxos.

## Requisitos

- R1. QUANDO o texto contém um e-mail (ex.: `ana.souza@exemplo.com.br`), O SISTEMA DEVE substituí-lo por `[EMAIL]`.
- R2. QUANDO o texto contém um telefone brasileiro, fixo ou celular, com ou sem `+55`, DDD entre parênteses, espaços, hífens ou pontos (ex.: `(11) 98765-4321`, `+55 11 3456-7890`, `11987654321`), O SISTEMA DEVE substituí-lo por `[TELEFONE]`.
- R3. QUANDO o texto contém um CPF com ou sem pontuação (`123.456.789-09`, `12345678909`), O SISTEMA DEVE substituí-lo por `[CPF]`. Onze dígitos soltos são tratados como CPF mesmo sem dígito verificador válido (dados fictícios raramente o têm).
- R4. QUANDO o texto contém uma URL de perfil pessoal (LinkedIn, GitHub, GitLab, Behance, Instagram, Facebook, X/Twitter, Medium, ou site próprio no cabeçalho), com ou sem `https://`/`www.`, O SISTEMA DEVE substituí-la por `[URL]`.
- R5. QUANDO o texto contém uma URL que não é de perfil pessoal (ex.: `https://docs.python.org/3/`), O SISTEMA DEVE mantê-la intacta.
- R6. QUANDO `mask_cv` recebe um CV, O SISTEMA DEVE substituir o nome do cabeçalho (primeira linha não vazia, se ela parecer um nome: 2 a 5 palavras, só letras/partículas `da/de/do/dos/das/e`, sem dígitos nem `@`) por `[NOME]`, e também todas as outras ocorrências desse nome completo e das suas palavras próprias (≥ 3 letras, exceto partículas) no resto do texto, sem diferenciar maiúsculas.
- R7. QUANDO a primeira linha não vazia do CV não parece um nome (ex.: `Currículo`, `Desenvolvedor Python`... ver pergunta 2), O SISTEMA NÃO DEVE mascarar nome, mas DEVE aplicar R1–R4.
- R8. QUANDO o texto não contém dado pessoal, O SISTEMA DEVE devolvê-lo idêntico (mesmos caracteres, mesmas quebras de linha).
- R9. QUANDO a função é aplicada duas vezes, O SISTEMA DEVE dar o mesmo resultado da primeira (idempotente: `[EMAIL]` etc. não são remascarados).
- R10. QUANDO o texto contém números que não são dados pessoais (anos `2019–2023`, versões `3.12`, valores `R$ 8.500,00`, porcentagens), O SISTEMA DEVE mantê-los.
- R11. QUANDO o CV de exemplo fictício (`tests/fixtures/pii/cv_example.md`) passa por `mask_cv`, O SISTEMA DEVE devolver um texto em que nenhum dos dados pessoais listados no fixture aparece.

## Fora de escopo

- Chamar `pii.py` a partir de `llm.py`, `prep_graph`, API ou CLI (tarefas que criam esses fluxos).
- Detectar nomes de pessoas fora do cabeçalho do CV (ex.: "meu nome é João" numa resposta da entrevista) — exigiria NER/modelo; ver pergunta 1.
- Endereço, CEP, RG, data de nascimento (não estão no "Pronto quando").
- Guardrails do Bedrock (tarefa de infra).
- Reverter o mascaramento (não há mapa placeholder → valor original).

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `src/mia/pii.py` | criar | regex compiladas + funções abaixo |
| `tests/test_pii.py` | criar | testes parametrizados (≥ 10 casos) |
| `tests/fixtures/pii/cv_example.md` | criar | CV fictício com nome, e-mail, telefone, CPF, LinkedIn, GitHub |
| `tests/fixtures/pii/cv_example_pii.txt` | criar | lista (um por linha) dos valores pessoais que não podem sobrar |

**Interfaces**

```python
EMAIL: Final = "[EMAIL]"
PHONE: Final = "[TELEFONE]"
CPF: Final = "[CPF]"
URL: Final = "[URL]"
NAME: Final = "[NOME]"

def mask_text(text: str) -> str: ...              # R1–R5, R8–R10: tudo que o visitante digita
def mask_cv(cv_text: str) -> str: ...              # R6–R7 + mask_text; CV da CLI e geração de fixtures
def extract_header_name(cv_text: str) -> str | None: ...   # R6/R7, exposta para teste
def mask_name(text: str, name: str) -> str: ...    # nome completo + palavras próprias → [NOME]
```

**Decisões**

- Só stdlib (`re`); nenhuma dependência nova. Regex compiladas no módulo, uma por tipo.
- Ordem fixa em `mask_text`: e-mail → URL → CPF → telefone. E-mail antes de URL (domínio do e-mail não vira URL); CPF antes de telefone (11 dígitos de CPF não viram telefone).
- Telefone exige formato de telefone BR (DDD de 2 dígitos + 8 ou 9 dígitos, opcional `+55`), com limites de palavra para não pegar trechos de números maiores.
- URL pessoal = domínio na lista de redes sociais (R4). "Site próprio" só é mascarado em `mask_cv`, nas primeiras linhas do cabeçalho (ver pergunta 3).
- Substituição de nome com `\b` e `re.IGNORECASE`, nome completo antes das palavras soltas.
- Funções puras, sem I/O nem log do texto original (não vazar PII em logs).

## Notas de implementação

- Passo 1: regex só com `re`; ordem e-mail → CPF → telefone. Lookbehind `(?<![\w+])` no telefone evita casar dentro de outros números; `11987654321` (11 dígitos soltos) vira `[CPF]`, como diz R3.
- Passo 2: `_URL_RE` com lista de domínios de redes sociais, scheme/`www`/subdomínio opcionais; lookbehind `(?<![\w.@/-])` evita casar `box.com` ou `/github.com` dentro de caminho. Ordem: e-mail → URL → CPF → telefone. Site próprio (R4/pergunta 3) fica para `mask_cv` no passo 3.
- Passo 3: nome do cabeçalho = 2–5 palavras só de letras (`[^\W\d_]+`); `mask_cv` aplica `mask_text` e depois `_ANY_URL_RE` só nas 5 primeiras linhas (site próprio), e por fim `mask_name` (nome completo, depois palavras ≥3 letras sem partículas). Fixture com cabeçalho de 5 linhas para o site entrar na janela.
