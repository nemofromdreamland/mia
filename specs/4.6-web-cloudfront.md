# 4.6 — Frontend em S3 + CloudFront

Aprovação: modo autônomo pedido pelo dono.

## Contexto

O front React/Vite (`frontend/`, Fase 3) vira site estático: bucket privado `mia-web-<conta>` servido só pelo CloudFront, com a API (4.2) liberada por CORS apenas para o domínio do CloudFront. Fontes: TRD ("Infraestrutura": linhas Frontend e Borda pública), Backend Schema ("S3": bucket separado `mia-web-<conta>`, servido só pelo CloudFront), `frontend/src/lib/api.ts` (`VITE_API_BASE_URL`).

## Requisitos

- R1. O SISTEMA DEVE criar o bucket `mia-web-<conta>` com Block Public Access total, SSE-S3 e `BucketOwnerEnforced`, legível apenas pela distribuição CloudFront (OAC + política com `AWS:SourceArn` da distribuição).
- R2. O SISTEMA DEVE criar uma distribuição CloudFront com `default_root_object = index.html`, HTTPS obrigatório (redirect), política de cache gerenciada `CachingOptimized`, headers de segurança gerenciados (`SecurityHeadersPolicy`), `PriceClass_100` e certificado padrão `*.cloudfront.net`.
- R3. QUANDO o caminho pedido não existe no bucket (rota do React Router, ex. `/recrutador`), o CloudFront DEVE responder `/index.html` com 200 (403 e 404 do S3 → `index.html`).
- R4. O CORS do API Gateway DEVE aceitar exatamente `https://<domínio do CloudFront>` (sai a variável `cors_allowed_origins` da 4.2).
- R5. QUANDO `scripts/deploy_web.py` roda, O SISTEMA DEVE: ler `api_url`, `web_bucket` e `web_distribution_id` do `terraform output`; rodar `npm run build` em `frontend/` com `VITE_API_BASE_URL` = `api_url` sem barra final; `aws s3 sync dist/ s3://<bucket> --delete` com `Cache-Control` imutável em `assets/` e `no-cache` em `index.html`; criar invalidação `/*`. Com `--dry-run`, só imprime.
- R6. QUANDO a URL do CloudFront é aberta, O SISTEMA DEVE mostrar o Início com os 5 casos (chamadas à API passam pelo CORS).

## Fora de escopo

- Domínio próprio/ACM, WAF, logs de acesso do CloudFront, CI do deploy (4.8).
- Mudanças no código do front (só a variável de build).

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `infra/web.tf` | criar | bucket web + sub-recursos, OAC, distribuição, política do bucket |
| `infra/api.tf` | alterar | CORS com o domínio do CloudFront |
| `infra/variables.tf` | alterar | sai `cors_allowed_origins` |
| `infra/outputs.tf` | alterar | `web_url`, `web_bucket`, `web_distribution_id` |
| `scripts/deploy_web.py` | criar | build + sync + invalidação |
| `tests/test_infra.py`, `tests/test_deploy_web.py` | alterar / criar | estáticos + executor falso |

**Interfaces**

```python
def outputs(run: Runner) -> dict[str, str]: ...          # terraform output -json
def api_base(url: str) -> str: ...                        # sem barra final
def deploy_commands(bucket: str, distribution: str) -> list[list[str]]: ...
def main(argv: Sequence[str] | None = None, run: Runner = ...) -> int: ...
```

`Runner`/`run_command`/`CommandError` reaproveitados de `scripts/push_image.py` (o `npm run build` recebe o env pelo executor).

**Decisões**

- SPA via `custom_error_response` (403/404 → `/index.html`, 200): simples e sem CloudFront Function. Efeito colateral aceito: arquivo inexistente também devolve o `index.html`.
- CORS só com a origem do CloudFront, conforme o TRD; o dev local continua usando o proxy do Vite (`/api`).
- Dois `s3 sync`: `assets/` (nomes com hash) com `max-age=31536000, immutable`; o resto com `no-cache`.
- `PriceClass_100` (América do Norte/Europa; Brasil cai no edge mais próximo): o mais barato, sem custo por hora.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| bucket web | HCL | nome `mia-web-${`, public access block, OAC `sigv4`, política com `cloudfront.amazonaws.com` + `AWS:SourceArn` |
| distribuição | HCL | `index.html`, `redirect-to-https`, IDs das políticas gerenciadas, `PriceClass_100`, 403 e 404 → `/index.html` 200 |
| CORS | HCL | `allow_origins = ["https://${aws_cloudfront_distribution.web.domain_name}"]` |
| api_base | `https://x.execute-api…/` | sem `/` final |
| ordem | executor falso | `npm run build` (env com `VITE_API_BASE_URL`) → sync `assets/` → sync resto → invalidação `/*` |
| dry-run | `--dry-run` | só `terraform output`; nada de npm/aws |
| falha do build (erro) | npm falha | 1, sem sync |

## Critérios de aceite

- [ ] URL do CloudFront abre o Início com os 5 casos — `curl` do `index.html` + `curl` com `Origin` na API (header CORS) + abrir no navegador
- [ ] `/recrutador` direto na URL → 200 com o app
- [ ] `apply` e upload aprovados pelo dono
- [ ] `uv run pytest` e `uv run ruff check .` passam

## Perguntas em aberto

- SPA por `custom_error_response` ou CloudFront Function? → resposta: `custom_error_response` (recomendado).
- Rotear `/api` pelo próprio CloudFront (sem CORS)? → resposta: não; o TRD pede CORS só do CloudFront (recomendado manter).
