# 1.10 — CLI `mia simulate` com repositório em memória

## Contexto

Primeira vez que as peças da Fase 1 rodam juntas: CV + vaga fictícios → `prep_graph` (1.6) → entrevista por texto no terminal (`interviewer`, 1.7, com o juiz da 1.8) → `report_graph` (1.9) → relatório em JSON. A sessão segue o ciclo de vida do caminho local (`preparing → ready → in_progress → scoring → completed`, ou `failed`) com `visitor_id = "local"` e fica num repositório em memória, primeira implementação da regra "interface + memória + DynamoDB". Fontes: IMPLEMENTATION_PLAN 1.10; BACKEND_SCHEMA "Visão geral" (fluxo local), "Ciclo de vida da sessão", "DynamoDB" (`mia-sessions`, `mia-turns`), "Sessão"; TRD (prep_graph na CLI); PRD RF-16.

## Requisitos

- R1. QUANDO o usuário roda `mia simulate --cv <arq> --job <arq> --persona <hr|technical|manager>`, O SISTEMA DEVE executar preparação → entrevista → relatório e terminar com código 0.
- R2. QUANDO `--cv`, `--job` ou `--persona` faltar ou a persona for inválida, O SISTEMA DEVE sair com código 2 (padrão do `argparse`) sem chamar modelo.
- R3. QUANDO o arquivo `--job` não existir, O SISTEMA DEVE escrever uma mensagem curta em `stderr` com o caminho e sair com código 1, sem chamar modelo.
- R4. QUANDO a simulação começa, O SISTEMA DEVE criar uma `Session` com `visitor_id = "local"`, `case_id = None`, `status = "preparing"`, `mode = "text"`, a persona e o idioma pedidos, e um `session_id` novo e único.
- R5. QUANDO `run_prep` terminar com sucesso, O SISTEMA DEVE gravar na sessão `status = "ready"`, `fit_score` e `job_title` (se houver na triagem/plano — ver P4).
- R6. QUANDO `run_prep` levantar `PrepError` (inclui `PrepValidationError`) ou `LLMInvalidOutputError`, O SISTEMA DEVE gravar `status = "failed"` e `error` (mensagem curta), escrever a mensagem em `stderr` e sair com código 1.
- R7. QUANDO a entrevista começa, O SISTEMA DEVE gravar `status = "in_progress"` e `started_at`, salvar o primeiro turno e mostrar a fala do entrevistador.
- R8. QUANDO o usuário digita uma resposta, O SISTEMA DEVE chamar `interviewer.answer`, salvar o turno respondido (substituindo o de mesmo `turn_no`) e o próximo turno, atualizar `current_question_id`, `follow_ups_used` e `turn_count`, e mostrar a próxima fala.
- R9. QUANDO a resposta for vazia ou passar do limite (`InterviewError`), O SISTEMA DEVE mostrar a mensagem e pedir de novo, sem salvar turno.
- R10. QUANDO o usuário digita o comando de encerrar (`/fim`, ver P2) ou envia EOF (Ctrl+D/Ctrl+Z), O SISTEMA DEVE chamar `end_interview(..., "visitor")` e seguir para o relatório.
- R11. QUANDO a entrevista termina (plano, limite ou visitante), O SISTEMA DEVE gravar `status = "scoring"` e `ended_at`, rodar `run_report` com os turnos do repositório, salvar os turnos devolvidos (com notas), gravar `overall_score`, `competency_scores`, `headline` e `status = "completed"`.
- R12. QUANDO o relatório estiver pronto, O SISTEMA DEVE imprimir em `stdout` um único JSON com `session_id`, `report` (`Report`) e `summary` (`CandidateSummary`), validável pelos schemas; falas e prompts interativos vão para `stderr` (ver Decisões).
- R13. QUANDO `run_report` levantar `ReportError` ou `LLMInvalidOutputError`, O SISTEMA DEVE gravar `status = "failed"` e `error`, escrever em `stderr` e sair com código 1.
- R14. QUANDO uma operação do repositório recebe `visitor_id` diferente do dono da sessão, O SISTEMA DEVE se comportar como se a sessão não existisse (`SessionNotFoundError`).
- R15. QUANDO `update_session` recebe um `expected_status` diferente do atual, O SISTEMA DEVE levantar `SessionConflictError` sem alterar nada (espelha o `UpdateItem` condicionado).
- R16. QUANDO os turnos são listados, O SISTEMA DEVE devolvê-los em ordem crescente de `turn_no`.

## Fora de escopo

- `mia simulate --case <id>` e `cases.py` (1.12); implementação DynamoDB (Fase 3); cotas e kill switch (`create_session` web, não CLI); API/FastAPI; voz.
- Guardar `report.json`/`summary.json` (S3) — o JSON sai no `stdout`; o usuário redireciona se quiser.
- Retomar sessão `failed` (`failed → preparing`): cada execução é uma sessão nova.
- Novas versões de prompt.

**Interfaces**

```python
# src/mia/repositories.py
class RepositoryError(Exception): ...
class SessionNotFoundError(RepositoryError): ...
class SessionConflictError(RepositoryError): ...

class SessionRepository(Protocol):
    def create_session(self, session: Session) -> None: ...
    def get_session(self, visitor_id: str, session_id: str) -> Session: ...
    def update_session(
        self, visitor_id: str, session_id: str, *,
        expected_status: SessionStatus, changes: Mapping[str, Any],
    ) -> Session: ...                        # também atualiza updated_at
    def put_turn(self, visitor_id: str, turn: Turn) -> None: ...   # upsert por turn_no
    def list_turns(self, visitor_id: str, session_id: str) -> list[Turn]: ...

class InMemorySessionRepository:  # implementa SessionRepository
    def __init__(self, clock: Clock = ...) -> None: ...

# src/mia/simulation.py
LOCAL_VISITOR: Final = "local"

class SimulationError(Exception): ...       # mensagem curta, vira stderr + saída 1

class SimulationDeps(BaseModel):            # arbitrary_types_allowed
    repo: SessionRepository
    decider: Decider
    writer: Writer
    scorer: Scorer
    clock: Clock
    prep: Callable[[PrepInput], PrepResult]           # padrão: run_prep
    report: Callable[[InterviewPlan, list[Turn]], ReportResult]  # padrão: run_report

def new_session_id(clock: Clock) -> str: ...          # ver P1
def prepare(deps: SimulationDeps, data: PrepInput) -> tuple[Session, PrepResult]: ...   # R4–R6
def begin(deps: SimulationDeps, session: Session, plan: InterviewPlan) -> tuple[InterviewState, Turn]: ...  # R7
def reply(deps: SimulationDeps, state: InterviewState, text: str) -> StepResult: ...   # R8, R9
def stop(deps: SimulationDeps, state: InterviewState) -> tuple[InterviewState, Turn]: ...  # R10
def finish(deps: SimulationDeps, state: InterviewState) -> ReportResult: ...  # R11, R13

def default_deps(persona: Persona, repo: SessionRepository | None = None) -> SimulationDeps: ...

# src/mia/cli.py
def build_parser() -> argparse.ArgumentParser: ...
def run_simulate(
    args: argparse.Namespace, deps: SimulationDeps,
    stdin: TextIO = sys.stdin, stdout: TextIO = sys.stdout, stderr: TextIO = sys.stderr,
) -> int: ...
def main(argv: Sequence[str] | None = None) -> int: ...
```

**Decisões**

- **Três camadas:** repositório (dados) / `simulation.py` (regras de estado, testável sem terminal) / `cli.py` (só I/O). A API da Fase 3 vai reaproveitar `simulation.py`-like com o repositório DynamoDB.
- **Repositório guarda cópias** (`model_copy(deep=True)`) para o chamador não mutar o estado interno. Chave `(visitor_id, session_id)`, como a tabela.
- **Interface como `typing.Protocol`** (sem herança obrigatória); a implementação DynamoDB virá com o mesmo contrato.
- **`InterviewState` não é persistido inteiro:** na CLI ele vive na memória do processo; o repositório recebe os campos da tabela (`current_question_id`, `follow_ups_used`, `turn_count`) e os turnos. Reconstruir estado a partir do repositório fica para a API.
- **stdout só com o JSON final** (R12), para `mia simulate ... > relatorio.json` funcionar; o diálogo vai para `stderr`.
- **Injeção de dependências** (`SimulationDeps`): testes usam decider/writer/scorer/prep/report falsos e relógio fixo; `default_deps` monta os reais (`should_follow_up`, `default_writer(persona=...)`, `default_scorer`, `run_prep`, `run_report` com `scorer`).
- **`level` e `estimated_minutes` do `PrepInput`:** a assinatura da tarefa só tem `--cv --job --persona`; proposta de opcionais `--level` (padrão `junior`) e `--minutes` (padrão 20) e `--language` (padrão `pt-BR`) — ver P3.
- **Nada de SDK aqui**; erros de configuração do provedor (`ModelConfigError`, como nos demos) viram mensagem curta + saída 2? — ver P5.
- Sem dependências novas (ULID: ver P1).

## Notas de implementação

- Passo 1: testes vistos falhando (`ModuleNotFoundError: mia.repositories`). Interface é `Protocol` com `@runtime_checkable` (teste confere `isinstance`). `Clock` definido localmente (não importa `interviewer`, para o repositório não depender da camada de entrevista). Guarda e devolve cópias profundas. `update_session` revalida a `Session` inteira (valor inválido → `ValidationError`, que é `ValueError`, sem alterar nada) e recusa mudar `visitor_id`, `session_id`, `created_at` e `updated_at`. `put_turn` com mesmo `turn_no` substitui. Suíte: 487 passed, cobertura 99,73%.
- Passo 2: testes vistos falhando (`ModuleNotFoundError: mia.simulation`). `new_session_id` gera ULID à mão (timestamp do `clock` em ms + 80 bits de `secrets`, Crockford base32). `SimulationDeps` é `frozen`; `prepare` cria a sessão `preparing` antes de chamar `prep` e, em `PrepError`/`LLMInvalidOutputError`, grava `failed` + `error` e levanta `SimulationError`. `begin` salva o 1º turno e passa a sessão `ready → in_progress` (com `started_at`, `current_question_id`, `follow_ups_used`, `turn_count`). `job_title` fica `None` (P4). Suíte: 495 passed, cobertura 99,74%.
