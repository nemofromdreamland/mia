# 5.2 — Ferramentas da entrevista por voz

## Contexto

O Sonic deve trocar apenas entrada e saída: plano, limites, decisões, juiz e persistência continuam sob controle determinístico do `interviewer.py` e do serviço. Esta tarefa liga a transcrição final do candidato à máquina de estados, agenda `score_answer` sem bloquear a próxima fala, aplica no servidor o limite de resposta falada e fornece dicas determinísticas sem revelar `look_for` nem chamar outro modelo.

## Requisitos

- R1. QUANDO uma sessão de voz pronta começa, O SISTEMA DEVE carregar o mesmo plano curto, persona, limites `WEB_LIMITS` e estado persistido usados pelo modo texto, sem permitir que o Sonic escolha pergunta, fase ou número de aprofundamentos.
- R2. QUANDO o Sonic solicita a entrega de uma resposta, O SISTEMA DEVE aceitar somente a ferramenta de alto nível `submit_answer` e usar internamente `time_check`, `should_follow_up`, próxima pergunta e `end_interview` do `interviewer.py`; nome, argumentos ou estado inesperados devem ser recusados sem gravar turno.
- R3. QUANDO uma transcrição final do candidato é entregue, O SISTEMA DEVE mascará-la com `pii.py` antes de qualquer chamada adicional a modelo e gravar somente o texto mascarado no turno correspondente.
- R4. QUANDO a resposta válida é processada, O SISTEMA DEVE decidir deterministicamente se encerra, aprofunda ou avança, persistir o turno respondido e o próximo turno na mesma ordem do modo texto e devolver ao Sonic apenas a fala curta do entrevistador.
- R5. QUANDO o turno respondido é persistido, O SISTEMA DEVE agendar `score_answer` em segundo plano, sem atrasar a próxima fala; sucesso atualiza somente aquele turno e falha mantém `score=None` para o relatório completar depois.
- R6. QUANDO a tarefa de nota termina após reconexão, repetição ou encerramento, O SISTEMA DEVE atualizar o turno de forma idempotente, sem executar nem sobrescrever uma nota já persistida.
- R7. QUANDO começa a captura de uma resposta falada, O SISTEMA DEVE aplicar no servidor a duração máxima configurada por `MIA_VOICE_ANSWER_MAX_SECONDS`, com padrão de 90 s, usando relógio monotônico e nunca confiando no cliente.
- R8. QUANDO a duração máxima é atingida, O SISTEMA DEVE fechar a entrada de áudio daquele turno uma única vez e entregar como resposta a transcrição final disponível até o limite; áudio e transcrições posteriores daquele turno devem ser ignorados.
- R9. QUANDO o limite é atingido sem qualquer transcrição não vazia, O SISTEMA DEVE manter a pergunta atual sem chamar decisão, juiz ou writer e devolver um resultado de resposta vazia para a camada de protocolo tratar.
- R10. QUANDO uma pergunta é apresentada, O SISTEMA DEVE disponibilizar 2 ou 3 dicas curtas, pré-geradas e versionadas no fixture do caso, sobre o que o visitante pode abordar como personagem, sem copiar nem derivar em runtime os `look_for`.
- R11. QUANDO as dicas são carregadas, O SISTEMA DEVE validar que cada pergunta do plano curto possui 2 ou 3 dicas, que nenhuma é vazia ou idêntica a `look_for`, e que sua obtenção não chama modelo.
- R12. QUANDO dicas são consultadas ou usadas, O SISTEMA NÃO DEVE incluí-las na resposta enviada ao juiz, alterar a nota, acionar uma chamada extra de modelo nem fornecer uma resposta pronta.
- R13. QUANDO o entrevistador fala por voz, O SISTEMA DEVE continuar usando o prompt `interviewer` v2 e `finish_at_sentence`, limitando cada fala a 3 frases curtas e 60 palavras.
- R14. QUANDO os testes rodam offline, O SISTEMA DEVE permitir Sonic, repositório, relógio e executor de tarefas falsos para verificar transições, limite, dicas, persistência e concorrência sem AWS.
- R15. QUANDO a integração é exercitada com AWS, O SISTEMA DEVE conduzir o plano curto por voz, avançar ou aprofundar como no texto, salvar os turnos somente em texto e iniciar a próxima fala antes da conclusão artificialmente lenta do juiz.

## Fora de escopo

- Transporte e áudio básicos do Sonic (5.1), protocolo WebSocket da MIA (5.3), timer/microcopy no navegador (5.4) e URL assinada (5.5).

**Interfaces**

```python
class AnswerHint(BaseModel): ...
class SubmitAnswerArgs(BaseModel): ...
class VoiceToolResult(BaseModel): ...
class VoiceAnswerLimit(BaseModel): ...

class ScoreScheduler(Protocol):
    def submit(self, job: ScoreJob) -> None: ...

class VoiceToolSession:
    def start_answer(self, turn_no: int) -> VoiceAnswerLimit: ...
    def receive_transcript(self, turn_no: int, text: str, final: bool) -> None: ...
    def expire_answer(self, turn_no: int) -> VoiceToolResult: ...
    def submit_answer(self, args: SubmitAnswerArgs) -> VoiceToolResult: ...
    def hints_for_current_question(self) -> tuple[AnswerHint, ...]: ...

def advance_interview(
    state: InterviewState,
    text: str,
    *,
    decider: Decider,
    writer: Writer,
    clock: Clock,
    limits: InterviewLimits = DEFAULT_LIMITS,
) -> StepResult: ...

def schedule_score(
    scheduler: ScoreScheduler,
    repo: SessionRepository,
    visitor_id: str,
    turn: Turn,
    question: Question,
    scorer: Scorer,
) -> None: ...

def put_turn_score_if_absent(
    self, visitor_id: str, session_id: str, turn_no: int, score: AnswerScore
) -> bool: ...
```

**Decisões**

- O Sonic vê apenas `submit_answer`; os nomes das ferramentas internas não viram autoridade do modelo. A camada valida a sessão e chama o fluxo existente.
- `answer` mantém compatibilidade com texto, mas a transição sem nota vira uma função separada. No modo voz, persistência e próxima fala acontecem antes de o scheduler chamar o juiz.
- O timer usa o relógio monotônico do servidor a partir do início aceito da resposta. A 5.3 bloqueará chunks posteriores e traduzirá o resultado para eventos; o front apenas espelha o prazo.
- As dicas ficam em `cases/<id>/hints.yaml`, mapeadas por `question_id`, escritas/revisadas manualmente a partir do CV fictício e da fase. Isso evita chamada extra e separa explicitamente dicas de `look_for`; mudar fixture eleva `version`.
- Dica não é anexada ao texto do candidato nem às variáveis do juiz. Se for necessário registrar uso após a revisão, será metadado separado, nunca conteúdo avaliado.
- O update condicional da nota evita corrida entre tarefa em background, reconexão e relatório final. A falha é observável, mas não bloqueia a entrevista.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| início | sessão `ready` de voz | mesmo plano curto e `WEB_LIMITS` do texto; pergunta atual persistida |
| ferramenta permitida | `submit_answer` + transcrição final | máscara, decisão, dois turnos persistidos e fala v2 devolvida |
| ferramenta desconhecida | `next_question` direto | erro; nenhum turno ou estado alterado |
| estado inválido | resposta duplicada ou turno antigo | recusada sem chamadas de modelo e sem escrita |
| nota lenta | scheduler falso retém job | próxima fala já disponível e turno inicialmente sem nota |
| nota concluída | job retorna `AnswerScore` | turno correto recebe nota sem alterar fala/resposta |
| nota duplicada | duas conclusões para mesmo turno | primeira nota vence; segunda não sobrescreve |
| falha da nota | scorer lança exceção | entrevista continua; `score=None` |
| limite padrão | sem env | prazo server-side de 90 s |
| limite configurado | env `MIA_VOICE_ANSWER_MAX_SECONDS=30` | expira exatamente em 30 s monotônicos |
| expiração com texto | parcial final disponível aos 90 s | captura fecha uma vez e texto disponível é entregue |
| expiração vazia | nenhum texto | pergunta não avança e nenhum modelo é chamado |
| chunk tardio | áudio/transcrição após expiração | ignorado; nenhuma segunda entrega |
| dicas válidas | cada pergunta dos 5 casos | 2–3 strings curtas, não vazias e distintas de `look_for` |
| dicas sem modelo | consulta repetida | resultado idêntico e zero chamadas LLM |
| juiz | resposta com dicas consultadas | scorer recebe somente resposta mascarada; resultado não depende das dicas |
| fala curta | writer v2 retorna cauda incompleta | no máximo 3 frases/60 palavras e `finish_at_sentence` aplicado |
| AWS | juiz falso demora durante conversa real | próxima fala começa antes da nota; turnos ficam somente em texto |

## Critérios de aceite

**Offline (não requer AWS)**

- [ ] Entrevista por voz falsa segue o plano curto, aplica limites e grava turnos mascarados somente em texto — verificar com: `uv run pytest tests/test_voice_tools.py -v`
- [ ] `score_answer` roda pelo scheduler e sua demora/falha não bloqueia a próxima fala — verificar com: `uv run pytest tests/test_voice_tools.py -v`
- [ ] O limite configurável é imposto pelo servidor e entrega uma única vez o texto disponível — verificar com: `uv run pytest tests/test_voice_tools.py -v`
- [ ] Os 5 fixtures fornecem 2–3 dicas determinísticas por pergunta, sem igualdade com `look_for` e sem chamada LLM — verificar com: `uv run pytest tests/test_case_files.py tests/test_voice_tools.py -v`
- [ ] O modo texto mantém o comportamento existente — verificar com: `uv run pytest tests/test_interviewer.py tests/test_service.py -v`
- [ ] `uv run pytest` passa
- [ ] `uv run ruff check .` passa

**Com AWS — depende de uma conta AWS nova**

- [ ] Entrevista por voz segue o plano e grava turnos em texto — verificar com conversa fictícia: `uv run python -m mia.voice.console`
- [ ] Com juiz artificialmente lento, a próxima fala é ouvida antes da nota terminar.
- [ ] Ao exceder o limite configurado, a captura encerra e o trecho falado é processado uma única vez.
