# 3.10 — Módulo do recrutador

Aprovação: modo autônomo pedido pelo dono.

## Contexto

As regras da tela do recrutador (Backend Schema, "Tela do recrutador: regras") já foram escritas dentro de `service.py` na 3.1 (`_case_average`, `_row`, filtro e ordenação inline em `list_recruiter_candidates`, comparação inline em `get_report`). O Implementation Plan (3.10) pede que elas vivam em `src/mia/recruiter.py`, testadas isoladamente com 0, 2, 3 e 10 sessões, e que a média venha da consulta por caso (GSI `by_case`, já usada por `DynamoSessionRepository.list_completed(case_id)`). Esta tarefa extrai as regras para funções puras, liga o serviço a elas e corrige o único ponto que ainda calcula a média a partir de todas as sessões (`get_recruiter_candidate` filtra a lista global em vez de consultar o caso).

## Requisitos

- R1. QUANDO um caso tem menos de 3 sessões concluídas (0 ou 2), O SISTEMA DEVE devolver média `None`, listar todas as concluídas e `delta_vs_case_avg = None` em cada linha.
- R2. QUANDO um caso tem 3 ou mais sessões concluídas (3 ou 10), O SISTEMA DEVE calcular a média de `overall_score` e listar só as sessões com nota estritamente maior que a média, com `delta_vs_case_avg = round(score − média, 2)`.
- R3. QUANDO há linhas, O SISTEMA DEVE ordená-las por maior `delta_vs_case_avg` primeiro e, no empate (ou sem média), pela sessão mais recente (`ended_at`).
- R4. QUANDO `CaseStats` é montado, O SISTEMA DEVE trazer `completed_sessions` e `average_score` arredondado a 2 casas (`None` com < 3).
- R5. QUANDO `get_report` responde uma sessão concluída, O SISTEMA DEVE preencher `is_above_case_avg` pela mesma regra (`None` com < 3; `True` só se nota > média).
- R6. QUANDO uma linha ou resposta do recrutador é montada, O SISTEMA NÃO DEVE conter `visitor_id` nem campo da `Session` fora de `RecruiterCandidateRow` (teste por serialização com visitor conhecido).
- R7. QUANDO `get_recruiter_candidate` calcula a média do caso, O SISTEMA DEVE usar `repo.list_completed(case_id)` (consulta `by_case`), não a lista de todas as sessões.

## Fora de escopo

- Mudar o contrato da API ou dos schemas (`CaseStats`, `RecruiterCandidateRow`, `RecruiterList`).
- Índice novo para achar uma sessão por `session_id` sem `visitor_id` (o detalhe continua achando a sessão pela lista de concluídas).
- Cache da média, paginação, frontend.

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `src/mia/recruiter.py` | criar | regras puras |
| `tests/test_recruiter.py` | criar | R1–R6 com 0, 2, 3 e 10 sessões |
| `src/mia/service.py` | alterar | delega a `recruiter.py`; remove `_case_average`/`_row`; R7 |
| `tests/test_service.py` | alterar | teste de R7 (repo espião) |

**Interfaces**

```python
# src/mia/recruiter.py
MIN_SESSIONS_FOR_AVERAGE = 3
def case_average(completed: list[Session]) -> float | None: ...
def is_above_average(score: float | None, average: float | None) -> bool | None: ...
def build_row(session: Session, average: float | None) -> RecruiterCandidateRow: ...
def case_stats(case_id: str, completed: list[Session]) -> CaseStats: ...
def above_average_rows(completed: list[Session]) -> list[RecruiterCandidateRow]: ...
def sort_rows(rows: list[RecruiterCandidateRow]) -> list[RecruiterCandidateRow]: ...
```

**Decisões**

- Funções puras sobre `list[Session]`: sem repositório, fáceis de testar com 0/2/3/10; o serviço continua dono do I/O.
- `MIN_SESSIONS_FOR_AVERAGE` passa para `recruiter.py`; `service.py` importa de lá (mantém o nome exportado).
- Linha montada campo a campo (como hoje): é o que garante R6.

## Plano de testes

| Caso | Entrada | Esperado |
| --- | --- | --- |
| 0 sessões | `[]` | média `None`; linhas `[]`; stats `(0, None)` |
| 2 sessões | notas 2.0 e 4.0 | média `None`; 2 linhas com delta `None`, mais recente primeiro |
| 3 sessões | 2.0, 3.0, 4.0 | média 3.0; 1 linha (4.0, delta 1.0) |
| 3 iguais | 3.0 ×3 | média 3.0; 0 linhas (estritamente maior) |
| 10 sessões | 1.0…5.0 variadas | média certa; só acima; ordem por delta, empate pelo `ended_at` mais recente |
| arredondamento | média 3.3333 | `average_score` 3.33; delta arredondado |
| is_above | (4.0, 3.0), (3.0, 3.0), (x, None) | `True`, `False`, `None` |
| anonimato | sessões com `visitor_id` "visitor-secreto" | JSON das linhas não contém o id |
| R7 | repo espião | `list_completed` chamado com `case_id` no detalhe |

## Notas de implementação

- Passo 1: funções copiadas do serviço sem mudar a regra (mesma chave de ordenação, mesmo arredondamento). `above_average_rows` reaproveita `is_above_average` (`None` = sem média → mostra; `False` → esconde). O teste de 10 sessões tem empate de delta (duas notas 4.5) para provar o desempate pelo `ended_at`. 14 testes; o serviço ainda não usa o módulo (passo 2).
- Passo 2: `service.py` perdeu `_case_average`, `_row` e a constante (sem outro uso no repo, então não foi reexportada; desvio da decisão da spec, que previa manter o nome em `service`). `get_report` usa `is_above_average`; `list_recruiter_candidates` usa `case_stats` + `above_average_rows` por caso e `sort_rows` no total. `get_recruiter_candidate` continua achando a sessão pela lista de concluídas (sem índice por `session_id`), mas a média agora vem de `list_completed(case_id)`; teste novo com repo espião prova a consulta por caso. Os 13 testes antigos do recrutador no serviço passaram sem mudança (regressão).
