# 2.1 — Golden set: 10 perguntas com `look_for`

## Contexto

O conjunto A de avaliação mede o juiz: 10 perguntas × 7 respostas = 70 itens (`docs/TRD.md` § Avaliação). Esta tarefa cria só as 10 perguntas, com rubricas (`look_for`) revisadas pelo dono; a 2.2 gera as respostas a partir delas. As perguntas usam o schema `Question` de `schemas.py` (`docs/BACKEND_SCHEMA.md` § Golden set, item `GoldenItem.question`) e partem dos 5 casos de `cases/` (`docs/CASES.md` § Como as fixtures são geradas, último parágrafo).

## Requisitos

- R1. QUANDO `evals/datasets/questions.yaml` é carregado, O SISTEMA DEVE validar cada item com o modelo `Question` de `src/mia/schemas.py`, sem erro.
- R2. QUANDO o arquivo é carregado, O SISTEMA DEVE conter exatamente 10 perguntas: 6 com `phase: technical` e 4 com `phase: behavioral`.
- R3. QUANDO o arquivo é carregado, todo `id` DEVE ser único e todo `look_for` DEVE ter de 3 a 4 critérios não vazios e distintos (o mínimo/máximo já vem do schema).
- R4. QUANDO uma pergunta é escrita, ela DEVE ser em português, fictícia e sem dado pessoal (nenhum nome, e-mail, telefone ou empresa real), e cada critério de `look_for` DEVE ser observável numa resposta (algo que dá para marcar presente/ausente).
- R5. QUANDO a tarefa termina, as rubricas DEVEM ter sido revisadas pelo dono do projeto (registro no evidence).

## Fora de escopo

- Gerar respostas (2.2), notas humanas e split (2.3), Promptfoo (2.5), métricas (2.6).
- Loader de produção em `src/mia/` para o golden set (a 2.2/2.5 decide onde ler o arquivo).
- Mudar `schemas.py`, prompts ou fixtures de `cases/`.

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `evals/datasets/questions.yaml` | criar | chave `questions:` com lista de 10 objetos no formato `Question` |
| `tests/test_golden_questions.py` | criar | valida R1–R3 lendo o YAML (sem chamar modelo) |

**Interfaces**

```python
# tests/test_golden_questions.py
QUESTIONS_PATH: Final[Path]               # <raiz>/evals/datasets/questions.yaml

def _load_questions() -> list[Question]: ...   # helper do teste; yaml.safe_load + Question.model_validate
```

Formato de cada item (campos de `Question`): `id` (ex.: `gq-tech-01`, `gq-beh-01`), `phase`, `competency`, `text`, `purpose`, `look_for`, `follow_ups` (até 3, pode ser `[]`), `targets_concern` (`null`).

**Decisões**

- **Reusar `Question` sem campo extra:** o `GoldenItem` embute um `Question` inteiro, então o golden set já nasce no formato que a 2.2 vai copiar. Nada de schema novo.
- **Rascunho a partir dos planos dos casos:** o agente propõe as perguntas inspirado em `cases/*/plan.json` (cobrindo vários casos/competências), reescrevendo para ficarem autocontidas (entendíveis sem o CV). O dono revisa e ajusta.
- **Teste só estrutural:** qualidade da rubrica (R4, R5) é revisão humana; o teste garante o que é verificável por código.
- `PyYAML` já é dependência (usada em `prompts.py`/`cases.py`); nenhuma dependência nova.
