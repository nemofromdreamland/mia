# 4.7b — RunRecords da produção em runs/

Aprovação: modo autônomo pedido pelo dono (opção "A", recomendada, escolhida pelo dono em 2026-11-17).

## Contexto

O critério da 4.7 pede "custo em `runs/`", mas no AgentCore o `RunRecord` é gravado em `/app/runs` dentro da microVM, que é efêmera e inacessível. A conta AWS fecha hoje (o dono não fará upgrade), então o custo por sessão da demo real (métrica do PRD; TRD "Observabilidade e custo": JSONL em `runs/` é a fonte de verdade) só sobrevive se for copiado para o repositório antes. O stdout do container já vai para o CloudWatch (`/aws/bedrock-agentcore/runtimes/mia_backend-…-live`).

## Requisitos

- R1. QUANDO `MIA_RUNS_STDOUT=1`, `append_run_record` DEVE, além do arquivo, imprimir no stdout uma linha `MIA_RUN_RECORD <json do RunRecord>`; sem a variável (CLI, testes, avaliações), nada muda.
- R2. O Terraform DEVE passar `MIA_RUNS_STDOUT = "1"` ao runtime.
- R3. QUANDO `scripts/pull_runs.py` roda, O SISTEMA DEVE buscar os eventos com `MIA_RUN_RECORD` nos log groups `/aws/bedrock-agentcore/runtimes/mia_backend-*`, validar cada linha com `RunRecord` e anexar em `runs/<data UTC>_aws-<experimento ou adhoc>.jsonl`, sem duplicar `run_id` já presente nesses arquivos; linha inválida é contada e ignorada.
- R4. O script DEVE imprimir um resumo: chamadas novas, inválidas, e custo total + custo por `session_id` (US$, 4 casas).

## Fora de escopo

- Langfuse; retenção dos log groups do AgentCore (a conta fecha hoje); dashboards.
- Mudar o `RunRecord` ou o cálculo de custo.

## Design

**Arquivos**

| Arquivo | Ação | Conteúdo |
| --- | --- | --- |
| `src/mia/llm.py` | alterar | `RUNS_STDOUT_ENV`, linha no stdout em `append_run_record` |
| `tests/test_llm.py` | alterar | R1 |
| `scripts/pull_runs.py` | criar | busca, valida, deduplica, grava, resume |
| `tests/test_pull_runs.py` | criar | eventos falsos |
| `infra/agentcore.tf`, `tests/test_infra.py` | alterar | R2 |

**Interfaces**

```python
RUNS_STDOUT_ENV: Final[str]          # "MIA_RUNS_STDOUT"
RUN_RECORD_MARKER: Final[str]        # "MIA_RUN_RECORD "
def parse_events(messages: Iterable[str]) -> tuple[list[RunRecord], int]: ...   # (válidos, inválidos)
def known_run_ids(runs_dir: Path) -> set[str]: ...
def write_records(records: list[RunRecord], runs_dir: Path, known: set[str]) -> list[RunRecord]: ...
def summary(records: list[RunRecord]) -> str: ...
def fetch_messages(logs: Any, prefix: str) -> list[str]: ...   # boto3 logs, paginado
def main(argv: Sequence[str] | None = None, logs: Any | None = None) -> int: ...
```

**Decisões**

- Flag por env (desligada por padrão): CLI e avaliações seguem gravando só arquivo.
- Prefixo `aws-` no nome do arquivo: não mistura com `runs/` local.
- O script usa boto3 (perfil `mia`) e importa `mia.schemas.RunRecord` — não chama modelo, então não fere a regra do `llm.py`.
- Registro já mascarado (`input` vem do `pii.py`); o CloudWatch é da própria conta.
